# 首次安装与使用验收

首次业务验收：2026-10-11；代码复审与回归：2026-10-12。安装说明见 [CLI 使用指南](../packages/cli/README.md) 和 [容器分发](DISTRIBUTION.md)。

## 交付范围

`@tessmora/cli` 提供逐步终端向导与 `setup/configure/start/stop/status/logs/doctor/open`。本机安装由独立 Compose project 管理网页、API、Pi、Celery 与三个存储服务；远程模式只连接已有服务。npm 安装阶段不启动服务或下载模型。

终端与网页共享服务端配置：按能力确定模型依赖（包括 Pi 独立模型），遮罩输入密钥，真实测试通过后保存，再按需准备本地模型。准备状态、下载缓存和数据目录持久化；支持返回、重试及中断后继续。网页提供示例导入、推荐问题和引用原文入口。

已有源码开发模式继续使用原配置。托管安装使用独立数据目录和随机管理凭证，不复用现有开发存储，也不触发既有资料重新解析。

## 2026-10-13 更新后旧素材空间不可见

通过 UU 远程对同一 WSL 实例核对持久化存储与运行中 API：MinIO 中同时存在入门示例和原 `wallpapers` 空间，但列表 API 仅返回入门示例。原空间的桶、元数据和对象仍在。只读访问原空间的元数据后，该进程的列表和网页立即恢复两个空间，网页显示原空间有 9 张图片；此恢复未修改存储或重新入库。

根因是托管模式延迟加载目录，却以“内存缓存非空”判断完整目录已加载。导入示例或先访问单个空间填入部分缓存后，列表永远跳过 MinIO 全量读取。修复以独立的完成状态和异步锁管理首次完整读取；创建、更新、删除先等待目录加载，完整读取成功后再发布快照。连接或权限错误保留已有缓存、允许重试，列表 API 返回 503，不能再把故障显示为没有资料。新空间也只在元数据持久化成功后加入缓存。
