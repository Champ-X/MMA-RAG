# Tessmora 桌面端实施方案

**macOS Apple Silicon 内部版已交付，2026-11-24。** 源码基线为 `main@41691cd41e7f`。下列里程碑描述完整产品目标，供后续 Agent 继续实现。当前安装包、验收证据和待完成的正式发行工作见[桌面端实施记录](implementation-status.md)。

用户应能在一台干净的电脑上安装 Tessmora，导入一份手册和一段录像，关闭窗口后让入库继续，重启后从回答里的引用回到原页或原时间段。已经自托管 Tessmora 的用户应能用同一个应用连接服务器，在远程知识库中完成同样的研究。这两条用户路径决定首版范围和验收顺序。

## 1. 用户、运行方式与平台

主要用户是个人研究者、分析人员和多媒体资料整理者。默认使用者拥有一个系统账户和一个本地工作区，希望自己选择资料目录、模型服务和后台任务。第二类用户是已有可信自托管实例的研究者，他们需要从个人电脑访问那台服务器。服务器管理员继续通过现有部署流程管理服务。团队账户、跨设备实时同步和知识库 ACL 属于另外的产品范围。[产品定位](../../PRODUCT.md) · [现有工作区边界](../../SECURITY.md)

| 用户操作 | 本地工作区 | 远程工作区 |
| --- | --- | --- |
| 首次打开 | 选择资料目录，检查磁盘，准备签名运行包，再按所选能力配置模型。安装、启动和修复由应用完成，目标机器可以没有 Docker、Python、Node 或开发工具。 | 输入受信任实例的 HTTPS 地址，通过其认证，确认协议与能力。可直接进入远程模式，本机只需要桌面客户端。 |
| 导入与提问 | 原件、索引、作业和 Pi 账本在本机。界面在首次使用云端解析、嵌入、生成或媒体观察前说明发送哪些资料、使用哪个提供商。 | 使用服务器的知识库、索引和模型配置。选择本机文件后，界面显示目标工作区并上传文件内容。服务器负责持久化，客户端保存本工作区的会话视图。 |
| 关闭、退出与断线 | 关窗可让已启动的作业继续，状态栏或托盘提供重新打开和退出入口。显式退出先保存可恢复点并停止自有进程。下次打开后按作业类型恢复。 | 断开 Pi 订阅后任务继续，重连按事件游标续接。普通对话流中断时保留已收内容。用户显式取消 Pi 任务才向服务器发送取消。启停、更新、备份和服务器日志管理归部署者。 |
| 离线与故障 | 已下载并验证的本地能力可按能力清单使用。依赖云端的任务明确显示待联网、可重试或需要处理。 | 离线时显示断线和最后同步时间。重新连接后核对服务端状态，再开放相应操作。 |

**平台建议。** macOS Apple Silicon 是首个完整本地版候选平台。Windows x64 从 M0 开始构建和启动真实原生程序，通过相同的本地和远程验收后再列为正式支持。macOS Intel、Windows ARM64 和 Linux 原生安装包列入后续评估，现有 Web/容器入口仍可服务这些用户。最低 OS 版本、最低磁盘和内存要由 M0 指定候选值、由干净系统实测确认。现有发行 CI 测试的是 Linux 容器的 AMD64 和 ARM64。[发行工作流](../../.github/workflows/distribution.yml)

## 4. 客户端、工作区与本地进程

**建议的代码位置。** 在 `packages/desktop/` 放 Electron 主进程、preload、原生运行包管理和桌面验收入口。渲染进程加载本次安装随附的 `frontend` 构建产物。保持 Web 构建独立可用。只在操作确有桌面差异时提供适配，例如选择目录、打开已授权的原件、显示系统通知。preload 为每个动作提供具名方法，主进程校验调用窗口、工作区和参数。开启沙箱与上下文隔离，只给打包的主界面开放这些方法。用户导入的 HTML、SVG 等活动内容使用无桌面权限的隔离预览或下载。外部网页在系统浏览器打开。

**连接。** 建议为每个连接保存稳定的 `workspace_id`、模式、用户名称或别名、服务地址及协议版本。每个工作区独享 Electron 会话分区、凭证引用、历史与附件缓存。只允许当前受信任窗口通过同源的 `/api` 和媒体路由访问所选实例。代理流式转发请求与响应，保留中断信号、状态码、Range、缓存及内容类型。工作区凭证由主进程按目的地附加，重定向和对象存储地址分别核对授权。网页不能将代理当作任意 URL 或本机文件读取器。[现有 Nginx 行为](../../deploy/nginx.conf) · [受保护的 Pi 媒体及 Range](../../backend/app/api/pi_agent.py)

**认证与协议协商。** 本地后端保护资料、上传、检索、配置、流式响应及媒体的所有敏感读写。若使用回环端口，API 和 Qdrant 分别验证实例凭证，API 限制 Host/Origin，本地模式使用精确的来源白名单。系统凭证库保存工作区与模型密钥，运行时通过受限进程通道取得所需值。诊断日志剔除密钥、签名链接和原文。备份按第 7 节保存原件，服务凭证只保留引用。远程模式由服务器或其认证网关覆盖所有业务接口。建议新增版本化能力响应，列出工作区身份、API 兼容范围、认证方式、存储和媒体能力。旧版通过受控探测使用已验证能力，无法确认实例身份或受保护访问时给出修复说明。现有 `/health`、安装 token 和只覆盖 `/api/pi` 的 Cookie 各有独立用途。[当前接口与凭证](../../SECURITY.md) · [现有会话接入](../../frontend/src/lib/setupSession.ts)

本地配置保存和读取要同时接入凭证库。现有托管安装从 `state/setup.json` 解析服务商密钥。桌面实现应让设置页测试、保存、worker 重启和 Pi 恢复都按凭证引用取值。系统凭证库锁定或换机时提示解锁或重新授权。用测试凭证轮换一次并检查数据目录、普通备份和诊断包，才能确认旧写入路径已被覆盖。[托管凭证读取](../../backend/app/core/runtime_paths.py)

**进程归属。** 本地模式由管理器取得工作区独占锁，检查剩余空间、端口与包版本，依次准备对象目录和账本、启动 Qdrant、FastAPI、入库 worker，再检查索引与对象存储。Pi worker 仍按运行需要由 Python 宿主启动。向 UI 区分“可打开工作区”“存储就绪”“所选能力可用”。监测自有子进程、有限退避重启，记录退出原因。关窗继续运行时有可见退出入口。显式退出、系统关机或更新时先停止领新任务、保存或标记在途作业，再有序停止子进程并释放锁。异常退出后由新管理器验证工作区锁和进程归属，避免重复启动或误停外部实例。远程模式直接跳过本地运行包下载和进程启动。

## 5. 存储、索引与媒体

建议首次导入时把文件**复制进工作区**。文件名和原始路径作为展示信息，拖入的原件之后被移动或改名，库内引用仍应有效。按以下职责规划数据归属，物理目录可随平台调整。

| 数据 | 本地版的所有者与读写规则 | 备份策略 |
| --- | --- | --- |
| 原件、派生媒体、文档检查点 | 对象存储接口保存逻辑标识、长度、摘要、MIME、元数据和标签。本地实现用工作区对象目录和 SQLite 目录表。保留旧 `bucket/object_path` 别名，校验对象键并限制在已授权目录内。 | 原件、检查点及被历史引用的派生物进入备份。记录内容哈希，验证引用实际能读回对应字节。 |
| 知识库目录、本地任务与配置 | 建议共用一份工作区 SQLite 数据库，用事务提交对象版本、作业和待执行的索引变更。公开 API 仍返回已有的知识库、文件和处理 ID。 | 记录格式版本、工作区 ID、上次迁移与未完成作业。写入停止时用 SQLite 备份 API 或完成 WAL 检查点后制作一致副本。 |
| 向量与知识库画像 | 原生 Qdrant 独立数据目录。保持 collection、point ID、向量名、维度、距离、稀疏向量、payload 索引和来源位置。保存嵌入模型、预处理与索引格式的指纹。 | 版本兼容的快照或完整逻辑导出。嵌入模型变化时在新索引重建并验证后切换。仅维度相同不足以复用旧索引。 |
| Pi、网络采集、普通对话和附件 | Pi 的运行账本、每次运行的 Durable 数据库、观察缓存和附件保持成组。采集保留下载检查点和入库回执。普通会话按工作区保存快照与附件，继续使用现有会话和附件 ID。 | 备份时停止相关写入并纳入同一清单。普通会话的浏览器导出见第 7 节。模型缓存、日志与可重建的临时文件单独列出。 |

**存储接口。** 先为现有 MinIO 实现建立行为测试，再提供文件系统实现。接口至少覆盖按知识库列举、元数据与标签、写入、获取长度与内容摘要、分段读取、复制、删除、资源 URL 解析及故障分类。区分对象不存在、无权访问、磁盘已满与存储不可用，尤其避免把存储故障显示成空知识库。修改安装服务、设置页和 CLI 新协议，使其探测当前配置的“原件存储”和“向量索引”能力。旧 CLI/服务组合沿用原响应结构，新增字段或版本协商后切换。就绪读取只查询状态，写入验证使用本工作区可清理的测试对象。[目录恢复测试](../../backend/tests/test_knowledge_catalog_recovery.py) · [现有安装测试](../../backend/tests/test_setup_service.py)

**媒体接口。** 统一从工作区、来源和修订解析原文、图片、音视频与 Pi 产物。访问前校验知识库或 Pi 运行的来源范围。支持全量读取、单区间 Range、`206`、无效区间 `416`、正确的 `Content-Range` 和内容类型，页面才能从引用跳到视频指定秒数。保留已有签名 URL 的刷新语义，持久记录以资源身份为准。远程存储的签名 URL 仅在已授权目的地使用，不附带桌面工作区或模型凭证。云模型需要文件输入时沿用提供商的受控上传适配，本机回环媒体地址只服务本机客户端。[引用媒体刷新](../../frontend/src/services/reference_media_url.ts) · [模型媒体输入](../../backend/app/core/llm/providers/aliyun_bailian.py)

## 6. 作业提交、中断与恢复

**普通入库需做的改动。** 本地模式在单文件、批量、目录导入、重试和采集进入入库时共享同一套“已接收”规则。建议采用下列顺序，外部 API 保持已有的 `processing_id` 和可查询进度。

1. 客户端在发送前为每个批次条目持久分配请求 ID。服务端流式写入工作区同一文件系统的暂存文件，边写边计算摘要并检查空间。文件安全写入后原子改名。在 SQLite 事务中关联工作区、知识库、文件 ID、修订、请求 ID、对象和作业，再向用户报告该文件已接收。批量按项返回结果。相同请求 ID 与输入重发时返回原回执，复用请求 ID 但变更输入时返回冲突。用户主动另行导入同一内容时保留独立文件身份。进程在改名与登记之间退出时，启动扫描可核对并清理未被引用的暂存对象。
2. 独立 worker 在短事务内领取到期任务，保存租约持有者、执行代次、心跳和尝试次数。作业只携带对象引用，由 worker 在需要时打开原件。把大媒体和目录导入的下游接口改成可接收文件路径或流，对仍需完整字节的解析器限定单次输入和并发，并在 UI 显示超限原因。解析、嵌入与 Qdrant 写入在事务外完成。检查点按输入摘要、解析器/模型版本和阶段记录。完成时只允许仍持有本次租约的 worker 提交结果。磁盘满、网络失败、模型拒绝和用户取消分别保留原因及允许的后续动作。
3. 原件、SQLite 与 Qdrant 各自提交。用稳定的文件修订和 point ID 重放同一步写入，并记录索引提交回执。在结果可见前核对文件仍存在、修订仍有效。删除和替换先登记意图，再清理精确匹配的对象及点，最后确认。重启后对账，可收回旧租约、补齐未确认写入，避免重复片段或让已删除文件重新出现。复用现有文档检查点、稳定点号、旧点清理和写入完成后释放所有权的测试。[文档恢复测试](../../backend/tests/test_document_recovery.py)
4. 对画像保留“累计增量、领取、构建确认后扣减”的语义。桌面用 SQLite 事务维护计数和待办，服务器使用已有 Redis/Celery 路径。单次文档重试或重复投递不得重复计入同一增量。将作业执行并发、视频处理并发和云请求并发分别限制，低磁盘或运行包更新时暂停领新任务。[画像触发逻辑](../../backend/app/core/portrait_trigger.py)

| 工作类型 | 进程重启或断线后的动作 | 界面应能解释的结果 |
| --- | --- | --- |
| 文件入库、画像 | 已持久接收且可安全重试的阶段重新领取，从最后有效回执继续。达到重试上限后保留原件和可操作的错误。 | 已接收、排队、阶段进度、需处理、取消或完成。已完成的同一修订只出现一次。 |
| Pi Durable / core | Durable 由现有宿主恢复符合条件的运行并按游标重放事件，已提交工具回执继续去重。core 中断后显示实际终态或现有暂停状态。显式取消是终态。 | 断线重连与取消是不同动作。主模型在途请求可能重新计费，结果未知的付费媒体观察沿用现有中断语义。[Pi 恢复契约](../pi-agent-durable.md) |
| 网络采集 | 重启后保留 `interrupted` 状态，由用户继续。核验下载进度、目标知识库、内容身份和已有入库回执。 | 不重复收录已确认素材，部分下载和需要重新授权的来源可见。[采集存储](../../backend/app/modules/collection/store.py) |
| 普通对话与外部调用 | 恢复最后保存的会话和附件。普通 SSE 中途结束时保存已有内容并标明中断。新入库任务对提供商请求记录“未发送、已确认、结果未知”，仅对可幂等或可查证的步骤自动重试。 | 用户可重试生成或确认再次付费。重启本身不会把未确认结果计入已成功作业。 |

## 7. 旧数据导入、备份与回退

迁移入口接受已识别版本的 CLI/Compose 安装或桌面备份。源码开发实例需显式指定服务地址和数据来源，由预检列出能够导出的范围。远程客户端可连接原服务器继续使用，也可导入由服务器管理员提供的备份。以下流程始终在新目录构建目标工作区，并保留最后一个可用版本。

1. **盘点与预检。** 记录源版本、知识库与实际 bucket 映射、原件与派生物数量、总字节、Qdrant 版本/集合/点数、模型指纹、Pi/采集/会话状态、可用空间及缺失项。检查写锁和源版本。数据目录、CLI 实例目录和系统凭证分开登记。对运行中任务先排空、挂起或记录实际中断状态。遗留上传若只剩 Redis 状态且缺原件，列为需重新选择来源的条目。[现有目录与备份范围](../DISTRIBUTION.md)
2. **制作一致快照。** 暂停源端写入，让所需存储继续提供受控导出。若只取得停机副本，在隔离目录用匹配版本恢复后再读。MinIO 通过对象接口导出字节、键、标签及元数据，Qdrant 导出快照或包含向量的完整点记录。数据库按各自的一致性机制备份。清单记录各部分版本、大小和 SHA-256。用户普通备份以凭证引用代替明文密钥，换机后重新授权。
3. **恢复到暂存工作区。** 复制原件、派生物与检查点，重建旧键到本地对象的映射，保留 `kb_id`、`file_id`、point ID、会话、Pi run/source ID、PDF 页码及时间段。分别恢复 Pi 宿主账本、单运行数据库、附件与采集回执。维护迁移日志，按条目校验后提交，同一清单重复导入应能续传或识别已完成。索引缺失、快照不兼容、模型指纹缺失或发生变化时，给出可核验的处理选项及成本。
4. **补齐浏览器独有的数据。** 现有普通会话服务端有进程内状态，对话快照和部分附件仅在用户原浏览器来源的 localStorage/IndexedDB 中。提供由用户在该来源触发的导出，按工作区关联导入附件与原 ID。导出器须能在旧实例所用的同源页面运行。若只能取得服务器备份，报告已恢复的资料和缺失的客户端历史。不同工作区中同名文件不能替代缺失附件。[当前持久化边界](../MMA_ARCHITECTURE.md) · [附件身份约定](../chat-inline-references.md)
5. **验证与切换。** 校验所有对象摘要、集合点数和关键字段，打开迁移前保存的 PDF 与视频引用、普通对话附件和 Pi 证据。校验通过后原子更新工作区注册信息，首次启动再次探测。中断或验证失败时继续使用原实例，并可从已校验条目重试。需要回退数据格式时恢复整组匹配版本的运行包与迁移前快照。已经在新版本写入的资料先单独保全并提示合并方式。

## 9. 可复现的验证环境

所有验收都从专用空工作区或其只读基线副本开始。已有个人工作区不能作为测试目录。M0 应交付下列输入和驱动，此后每个里程碑复用同一份清单。

- **样例资料。** 使用仓库已有的合成回滚手册。另用固定版本生成器制作两页 PDF，第 2 页含唯一短语 `CEDAR-17`，一份 XLSX 的 `B2` 值为 `17`，一段 12 秒的 MP4 仅在第 6 至 8 秒呈现蓝色标志并发声。导出第 7 秒的帧为 PNG，声轨为 WAV，作为独立图片与音频样例。另建与知识库文件同名、字节不同的会话附件。清单冻结资产 SHA-256、生成工具版本、页码及时间锚点。大文件在 QA 环境生成，Git 仅保存生成器、预期结果和小夹具。[合成回滚手册](../../evals/baseline_v1/corpus/ops-rollback.md)
- **两套工作区与模型输入。** 建立 A、B 两个测试工作区，同名手册包含不同标志。用隔离 Compose 实例形成服务器对照，保存旧版知识库、引用、普通会话附件、Pi 运行及采集回执。日常 CI 使用固定、可计数的模型响应，真实执行桌面界面、解析器、存储、索引、鉴权和媒体传输。发行候选另用获准的真实模型路由验证文档问答、媒体观察和 Pi。记录模型、调用次数、用量与失败，不在回执中写密钥。
- **机器与证据。** 固定 OS 构建号、CPU/架构、内存、磁盘、文件系统和应用/模型版本。测试控制机可有 Node 与 Docker，安装目标使用干净系统快照，用户 PATH 中没有 Docker、Python、Node、FFmpeg。每次运行输出独立的 `ops/desktop-qa/<运行号>/`，包含输入摘要、安装包摘要、步骤与断言、实际值、错误、耗时和脱敏日志。记录是否使用测试模型。每个支持声明能追溯到对应平台的通过记录。
- **拟新增 QA 入口。** 建议 M0 提供 `packages/desktop/qa/run.mjs`，由控制机调用。参数 `--case` 使用下文的用例名，`--target` 选择 `macos-arm64` 或 `windows-x64`，`--input` 指向已生成的输入清单（含基准提交、夹具、安装包、机器快照和服务地址），`--out` 指向本次新目录。驱动通过正常产品入口操作，故障在专用工作区从进程外注入。断言失败返回非零，缺平台、缺凭证和未运行需在报告中各自标明。

M1 实现后，可从仓库根目录重放远程工作区用例。

```sh
node packages/desktop/qa/run.mjs --case remote --target macos-arm64 --input ops/desktop-qa/inputs.json --out ops/desktop-qa/remote-001
```

下列是**现有**回归入口。按[贡献指南](../../CONTRIBUTING.md)准备依赖，用隔离服务运行触及存储的测试。桌面变更还应选择上表关联模块的回归，服务器基线继续使用 [Compose 发行测试](../DISTRIBUTION.md)。

```sh
npm --prefix frontend test

npm --prefix frontend run build

```

### M0 · 原生运行与基线（`native`）

1. 在控制机按固定提交构建 Compose 对照。创建第 9 节夹具，记录一次从导入到可检索的基线，以及每种引用打开的位置。生成两套原生运行包，在各自干净机器上从非源码目录启动 Qdrant、Python 和包内 Node。验证向量写入/读取、PyMuPDF 解析第 2 页、XLSX 读取、FFmpeg 探测时长、Pi worker 完成一次固定响应的请求。
2. 将程序和数据放在带空格、中文的路径，验证读写、退出、重开和双开时的文件锁。记录每平台的最低候选 OS、安装与模型下载字节、所需磁盘、首次可交互时间、首次可检索时间、峰值内存。将各预算的数值上限和测量口径写入输入清单，随机器快照和夹具冻结。后续变更预算需单列原因和变更前后的测量结果。对每项待验证假设注明通过、阻塞或采用的备选实现。
3. 通过条件为每个候选平台都产出可复查的实际运行结果。缺失二进制、锁失效或分发方式未确定的能力必须列出负责人和补测条件。只有通过的组合可以成为后续该平台的发布输入，其他平台的开发可继续。

### M1 · 连接已有工作区（`remote`）

1. 在空安装上跳过本地运行包，连接 A。打开工作台，查询回滚手册，检查回答中的三次 `/ready` 和 15 分钟观察期并点击来源。通过真正的渲染窗口观察 SSE 在结束前有增量，点击 PDF 第 2 页，拖动视频到第 7 秒。对合法范围核对 `206` 与字节，对越界请求核对 `416`。
2. 在 Pi 任务运行中断开再重连，按事件序号补齐结果，运行 ID 与证据一致。切换到 B，再切回 A，核对同名文件、历史、附件和凭证不串用。检查桌面进程树及运行包目录，远程模式的本机后端与模型下载次数应为零。
3. 分别连接当前受保护的基线实例、协议不兼容的实例和凭证失效的实例。不兼容或未授权时能重新选择连接，敏感操作被拒绝，凭证不进入日志和第三方媒体请求。通过条件为两工作区在中英文界面均能完成上述流程，远程任务与服务生命周期由远端保持。

### M2 · 本地运行与存储（`local-storage`）

1. 在干净目标机选择空目录，启动签名测试运行包。使用预先冻结的对象和索引夹具，通过真实接口创建/列举知识库、读取原件与派生物、定位文档及视频引用。用相同的存储行为测试分别驱动 MinIO 与本地实现，覆盖中文名、同名不同内容、旧对象键、缺对象、删除和磁盘写满。
2. 检查新工作区的就绪结果。仅安装本地对象存储与 Qdrant 时，原件读写和索引检查均通过。停止自有 Qdrant 后显示索引故障，重启后同一份数据再次可读。把惯用端口分配给无关测试服务，重开应用并尝试打开同一工作区两次。应用须复用工作区或给出可操作错误，无关服务持续运行。同一目录始终只有一个写入宿主。
3. 通过条件为已授权调用读回的所有夹具摘要一致，未授权的业务与媒体调用得到拒绝，故障不被呈现成空库。退出清理全部自有进程后再次启动，连接档案与引用仍有效。服务器模式通过原有存储及 CLI 检查。

### M3 · 可靠入库与恢复（`recovery`）

1. 在真实界面一次拖入 PDF、XLSX、MP4。在文件暂存后但作业尚未登记时、显示已接收后、写入部分索引后、索引完成但尚未提交回执时，分别终止自有 worker 或宿主并重启。用固定输入重发同一请求。在每个已接收文件上核对一个逻辑修订、一份可检索点集合和正确的最终状态。未确认的请求可安全重试，磁盘满时只能报告实际成功接收的条目。
2. 并发执行同一作业的重试、取消和文件删除，并在画像更新确认前重启。删除后关联对象和点不能因旧 worker 完成而回来。画像计数只在成功后扣除一次。对可重放的阶段核对检查点命中，对结果未知的付费步骤核对调用计数与用户提示。
3. 对一条 Pi Durable 任务分别执行关窗、退出、重新打开和显式取消。核对已有工具回执、最新游标与状态。另复现一次 core 中断和一次采集中断后手动继续。普通 SSE 中断也要保留与附件对应的历史。最后从空目录完整执行“导入 PDF 与视频 → 退出 → 重开 → 提问 → 点击原页/原时间段”。在专用夹具上丢失已接收原件、重复可见索引、重复已确认操作的数量均为零。

### M4 · 迁移、能力与质量（`migration`、`parity`）

1. 在基线 Compose 实例创建 PDF 引用、视频时间段、带同名附件的普通会话、Pi 证据和中断的采集任务。通过旧来源页面导出浏览器历史。输入同一冻结快照，在迁移中途停止并重跑两次。在独立目录打开备份结果，逐一核验对象 SHA-256、知识库/文件 ID、point ID/向量配置、旧引用位置和附件字节。故意移除一个副本内的对象或使用不兼容索引时，报告应精确指出缺项并保留源实例。缺少浏览器导出时明确提示客户端历史未恢复。
2. 实际准备文本、图片、音频、视频所需的能力包，并各验证一个导入、检索及引用案例。关闭网络后重开应用，核对已缓存对象和允许离线运行的能力，依赖提供商的步骤显示原因。对新安装、模型下载中断、恢复及能力包移除各记录一次真实状态转换。
3. 在服务器与桌面使用同一知识库快照、模型/解析器版本、查询集、模式、Top K 与预算。用已有评测工具分别比较 Direct 和 Pi，记录文档 Recall@K、证据组召回、失败题及页码/时间段。固定响应的必需证据和来源身份应全部匹配。真实路由至少各完成一条文档和一条媒体研究并人工打开最终引用。将结果与 M0 冻结的预算对照，样本或控制条件不匹配时标记不可比较。[评测口径与命令](../RETRIEVAL_EVALUATION_V2.md)
4. 在固定机器测三次冷启动、五次热启动和首次可用耗时。分别导入一份及四份合法的 128 MiB 测试媒体，在受控阻塞解析阶段测接收路径的增量峰值内存，另测整次入库的峰值、临时磁盘和耗时。将实测值与预先记录的资源预算逐项比较。所有宣称支持的平台都要完成迁移和质量用例，回执中列出任何未验收的能力。

### M5 · 发行候选演练（`release`）

1. 从干净机器安装上一版候选，建立带旧引用的工作区，挂起一个可恢复作业。通过候选更新渠道安装新版，核验发布者、运行包签名、数据格式和迁移回执，再打开旧引用并完成作业。重放时分别在下载中、签名验证后、数据迁移中、切换版本后首次启动前中断。每次得到一套版本匹配、可启动、可恢复的程序和数据。
2. 分别输入签名无效的测试包、受损的分段下载和空间不足的目标磁盘。核验拒绝执行未验证内容、显示修复办法，原工作区继续可恢复。测试卸载后保留资料，重新安装并重新授权后能读回。诊断包只包含脱敏版本、组件状态、错误码与必要日志。用已知的合成密钥和原文标志检查排除项，核对普通备份保留原件且排除明文密钥。
3. 为每个拟支持的 OS/架构记录签名校验结果、安装/更新/恢复、M1–M4 的通过记录、实际下载大小、可用空间和已知限制。提交安装包摘要、发布清单、恢复演练报告和第三方声明供发布评审。测试签名与正式签名的结果分列，正式支持以实际签名安装包的干净机器验收为准。

| 本次需评审的事项 | 建议默认值 | 后续判定依据 |
