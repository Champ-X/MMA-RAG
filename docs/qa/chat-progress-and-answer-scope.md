# 检索进度与回答范围修复（2026-09-27）

## 原因与修改

展开的思考面板把加载指示器与结果字段绑定：路由的默认 `weighted` 对象使运行提示条件恒为假；意图已有内容、检索已有子查询/关键词后也会隐藏指示器。旧 SSE reducer 又将每个阶段事件都视作完成，无法表达局部进度。Agent 一轮完成后等待下一次规划时只留下“本轮完成”。

- 将状态归约提取为 `frontend/src/lib/thinkingState.ts`，支持明确的 `stage_status`，兼容旧事件。自动模式的选择事件仍处于意图分析；重排事件保持检索进行中；生成准备阶段连续衔接。
- 检索服务推送开始、召回、重排和完成事件。Agent 推送 planning/searching/evaluating/completed，完成轮次记录与当前执行状态分开显示。
- 展开/折叠使用同一执行状态。旋转环、顶部流动细线仅在实际运行时出现；已完成路由的分数条不再持续扫光；系统减少动画时停止运动、保留文字状态。没有用计时器伪造完成进度。

“被我淘汰的候选”是模型生成正文，源自混合候选上下文与缺少正文范围限制。统一系统 Prompt 和上下文说明现要求仅展示支持答案的采用项，静默忽略无关/未采用材料；该约束覆盖所有意图、备用及精简 Prompt。用户明确要求比较/解释取舍时仍可讨论指定选项。未使用正则截断答案，以免误删正常比较、否定事实与后续段落。
