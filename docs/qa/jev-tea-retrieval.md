# 茶叶驯化史：Jev 开关对比与漏召回修复

日期：2026-09-27。查询：`介绍一下茶叶的驯化史`。使用本机已迁移的数据及真实模型 API，无重新解析或入库。

## 根因

用户给出的成功会话 `5c8d0a5f-474b-4d6d-bbd9-9838b3470e25` 为 Agent 模式，失败会话 `1a27417c-76dc-4770-b807-c3cf8643afb7` 为 direct 模式。历史 `agent_selection` 与实际 HTTP 访问日志均确认这一差异，因此不能把两次回答的差别直接归因于 Jev。

两次原问题首轮都正确路由至“生物科普”（`bfa-fec-e0-bf0-0ddce`），但只启用文本/图片检索。该库实际有 397 个 `video_shot_vectors` 点，独立文本、图片、音频索引各为 0。茶史证据保存在《鬼谷闲谈茶叶驯化史.mp4》的场景、画面和转写中。

原有按知识库实际模态补搜的逻辑仅对带 Agent routing hints 的子查询生效。直接检索和 Agent 原问题锚点没有这项补搜。结果在重排之前已经为空，Jev 重排没有删除这些证据。历史失败会话没有保存 Jev 阶段诊断，不能倒推其准确回退原因；本次新复测已记录该信息。

同一原始查询、同一数据、同为直接检索；开关在独立评测请求上下文中设置，没有修改用户的全局配置。以下为真实检索调用，各路径一次，不是延迟基准。

| 代码 | Jev | 返回候选 | 检索耗时 |
| --- | --- | ---: | ---: |
| 修复前 | off | 0 | 87.74 s |
| 修复前 | adaptive + replace | 0 | 72.50 s |
| 修复后 | off | 10 | 83.80 s |
| 修复后 | adaptive + replace | 10 | 77.68 s |

修复后两边的 10 条都来自目标茶史视频。Jev 意图分类调用成功，但复杂度概率为 0.46–0.47，高于接管门槛 0.20，因此按原设计回退 Qwen 意图处理；不是 Jev 错误或直接接管。修复后的 Jev 重排实际成功调用 `jev-1.13.0`，约 0.62 s。

另对同一份修复后 off 路径的 10 条原始候选、相同原问题、相同上下文进行冻结候选对比：Qwen 重排 0.550 s，Jev 0.522 s。两者均保留这 10 条相关片段，排序不同。这只能证明本案例的检索可用，不能据此声称 Jev 整体质量或速度更优，也没有放宽复杂度门槛或更改用户的全局重排配置。

## 实现

- 将原 Agent 专用的知识库模态补搜推广至普通、流式和 Agent 检索。仅根据已路由主知识库的库存补充一种缺失模态，不扩大知识库或文件范围，不对所有问题开启所有媒体。
- 保留明确媒体请求及文件选择策略；明确排除媒体来源、仅查文档等限制不触发补搜。库存查询失败时保留原检索策略。
- 流式事件更新实际采用的模态与原因，并携带 Jev 意图、重排阶段诊断。
- 历史消息和完成事件保存请求的 Jev 配置及实际接管/回退信息，便于今后区分“已开启”与“实际接管”。
- 空检索诊断包含视频索引数量；已有视频结果时，不再误报“请确认是否已对文本建索引”。
