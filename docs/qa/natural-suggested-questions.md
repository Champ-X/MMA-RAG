# 基于真实材料的自然推荐问题

2026-09-30，本机 `localhost:3001` / `localhost:8000`。

## 改动

此前问题池为空时，后端和前端分别用知识库名称或文件名拼接通用问题。现在首屏只读取经过筛选、带来源的问题池；缓存缺失时返回 `warming` 并在后台生成。前端有界轮询，切换范围时停止等待。材料不足或生成失败时显示空状态，不补模板卡片。

生成使用独立任务 `suggestion_generation`，主模型为 `deepseek:deepseek-flash`，故障备用为 `aliyun_bailian:qwen3.5-flash`。它不随聊天主模型选择变化。单次主模型预算 20 秒，总预算 35 秒；后台及上传后的生成并发上限为 2。

直接读取已存储的文档分块、图片 caption/description、音频 transcript/description、视频 scene_summary/caption/asr_text，不重新解析或向量化。恢复后的知识库先通过现有存储映射找到 Qdrant 原始 ID，采样仍同时限制知识库和所选文件。

模型输出问题、来源片段、原文引用和简短答案提示。问题要求具体、独立可读、有自然的兴趣切入点；图片也可生成按画面特征找素材的请求。同文件的描述和 ASR 可以关联，不同文件不能混接。原文引用、重复问题、临时文件名、悬空指代与部分缺乏因果依据的问题经过本地筛选。少于三条时只显示实际数量。

问题池策略版本为 `natural-evidence-v3`，旧模板及旧策略缓存不再展示。删除文件或知识库时更新持久化版本，使正在生成的旧结果失效；问题池写入使用跨进程锁和独立临时文件。上传完成后仍自动预生成，离线回填脚本复用同一生成器。

## 实测

七个现有知识库全部通过 DeepSeek Flash 生成了有效结果，共 31 条；每库 1～6 条。含证据读取的单库耗时为 5.0～7.4 秒。这是小规模本机验证，不是稳定延迟基准。

实际问题示例：

- 中国古典园林为什么爱种松竹梅和荷花兰花？
- 巴西庄园主怎么用债务把欧洲咖啡农困在农场？
- 唱着“故事的小黄花”的那首歌，主唱声音有什么特点？
- 有夜间亮灯、门前带喷泉的欧式市政厅照片吗？

更新后的首屏自动范围缓存请求三次实测为 0.877 / 0.801 / 0.973 秒；七个单库范围均返回本库问题。补充未缓存图片范围的最终检查：首次在 0.740 秒返回 `warming`，随后读到一条通过筛选的问题，整个等待过程为 3.935 秒。该次生成真实使用 DeepSeek Flash，模型耗时 1.763 秒。补充后的问题池共 32 条，最后三次自动范围读取为 1.313 / 1.623 / 1.813 秒。详情保存在 `data/natural-suggestions/background-verification.json`。

- 后端相关测试 137 项通过，包括多模态采样、来源隔离、后台去重/并发、删除竞态、跨进程写入及离线回填。

- 本机后端已更新，健康检查通过；前端实际服务模块已包含新的加载逻辑。重启前确认后端会话列表为空。
- 浏览器插件出现运行时加载错误，未完成浏览器目视验收。仓库缺少 ESLint 配置，未执行有效的 ESLint 检查。
- 引用核验与因果线索规则是保守筛选，不等价于完整的语义蕴含证明；图片描述与 ASR 本身的准确性仍受原解析结果影响。
