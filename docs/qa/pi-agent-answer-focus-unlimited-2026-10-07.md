## 原因与调整

1. 检索候选、研究依据和最终交付混在一起。Agent 会把“结合背景完成结果”理解成额外的背景报告，并把未选候选的介绍当成回答完整性的证明。之前要求全部计划证据出现在正文，也会推动模型扩写及堆引用。
2. 曾尝试用计划中的主次分类控制媒体展开，导致正文已经推荐并引用的备选 `peaky.png` 被隐藏。该机制已经撤销；所有正文实际引用的合法媒体均正常展示，原有来源身份去重继续生效。
3. 旧预算将复杂研究转入强制收尾，禁止新检索，并限制复读与修正机会。此前文档比较运行 `aca30257-0376-44fc-8764-877765a4a19c` 在 172,808 累计 Token 时因剩余额度无法容纳上下文而失败，真实计数尚未达到总上限也可能提前结束。

当前设计从任务理解、工具参数说明和临近写作的提示三处明确交付边界。Agent 自行把计划标为 ready/unavailable 后，同一个 Agent 的下一轮请求在研究工作数据之后收到通用写作提示：直接回答原始问题，默认精炼，只写匹配结果和必要理由；不介绍未选材料；用户要求的比较、排除理由和关键反证仍保留。全部研究工具继续可用，发现缺口可以继续研究。

没有新增语义评分器、回答后处理器或引用相关性过滤器。宿主检查已登记事项状态、真实缺口、引用身份、权限与媒体地址，不要求最终引用等于计划证据集合，也不因合法引用未加入计划而拒绝。素材主次分类不控制前端显示。提示词不含本例片名、歌曲名或文件名，执行分支也不按任务关键词选择模板。
