# 新会话推荐与直接检索阶段耗时

2026-09-27，本机 `localhost:3001` / `localhost:8000`。

## 推荐问题加载

迁移后的问题池和预计算目录为空。旧接口虽默认 `prefer_precomputed=true`，缓存未命中仍同步读取知识库画像、随机抽样文件预览、请求 LLM。抽样内容影响缓存 revision，使相同范围也可能无法复用。前端显式启用 LLM、允许等待 120 秒，失败后又向最多 10 个库请求画像和文件；数组引用及随机范围还会重复触发加载。

默认请求现在只读范围内的问题池或预计算快照，未命中时根据实际知识库/所选文件元数据返回建议，不等待 LLM 或预览。显式 `refresh=true` 或 `prefer_precomputed=false` 保留现场生成能力。空范围不会扩为全库；文件范围不混入整库问题；文件生成也不会覆盖整库快照。

前端按规范化范围及内容版本复用 60 秒缓存，合并同范围并发请求，隔离旧范围响应；8 秒超时会取消请求并提供本地元数据建议或重试状态。新增“换一批”，只重新抽取快速结果。删除失败后的画像/文件请求。

此外，一次性从 7 库现有画像与已解析材料生成了 22 条模板建议，用时 6.05 秒，没有模型调用或重新解析。部分推荐采用截断主题句，表达自然度有限；后续入库原有后台问题生成仍保留。快照过期或新库没有缓存时，也走快速元数据路径。

## 阶段耗时

意图解析、智能路由、检索策略、生成回答各自在标题右侧显示耗时，意图识别/查询改写和召回/重排另有子项耗时。服务端使用单调时钟计算，thought 发送当前阶段和全量快照，complete 与历史保存同一结果。前端只在活跃阶段按本地单调时钟递增，最终以服务端值固定，避免两端系统时间偏差。

重复进度消息不重启计时；路由补充意图信息不会让进度倒退。失败与停止会固定已用时间；本地停止快照有单独标识。历史消息不会重新计时，旧消息未记录的阶段耗时不补造。问候等快捷路径不为未执行阶段编造时间。Agent 每轮时间保持原样，并获得生成阶段时间。

真实查询“介绍一下茶叶的驯化史”，直接检索，保留用户当前 `force + force` Jev 设置，最终模型 `deepseek:deepseek-flash`：
