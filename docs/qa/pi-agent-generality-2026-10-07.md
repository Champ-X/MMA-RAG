## 发现及调整

| 初次设计中的限制 | 当前通用设计 |
| --- | --- |
| 提示偏重剧情、海报、歌曲和推荐理由 | 描述最终交付项、依据、缺口和用户所需格式；没有固定推荐模板或查询顺序。 |
| 每项 `ready` 都必须取得外部证据 | 分离 `sources` 与 `user_input`；改写、翻译、用户数值推导和按要求创作可绑定真实用户输入完成，无需强制检索。混合任务可同时登记两类依据。 |
| 最多 8 项、8 条选中证据，和记忆容量绑定 | 最多 32 项、100 个最终引用，沿用有限契约容量；原文工作记忆独立按可配置字符预算和完整序列化预算计量。不会因一项多证据而删掉其他要求。 |
| 固定保留开头 1000 个字符 | 默认按任务轮转分配；Agent 可指定已交付文本任意位置的区间，保留尾部条件、例外和结果，并保留原编号、偏移和来源标记。 |
| 初始拆解完全不可扩展 | 原要求身份、顺序、原句、依据类型及模态不可删改；可追加用户原句支持的遗漏要求。来源任务不能在失败后降级成用户输入任务。 |
| 只计原文字符，忽略元数据和 JSON 转义 | 完整计量输出；先缩小默认摘录，必要时明确省略工作集条目，最终选择不丢失。显式指定的区间不静默截短，无法容纳则拒绝并保留上一状态。 |
| 收尾一直保护最新原文批次，旧失败草稿不断累积 | 已全部就绪或明确缺口后，可归档最新原文批次，用逐字工作集收尾；有宿主持久化确认的旧失败草稿可整对归档，保留最新草稿、反馈和调用配对。 |
| 保留来源文字作为系统消息注入 | 计划与来源作为标明身份的用户级工作数据，不能提升来源指令的权限。真实 HTTP 测试核对了供应商收到的消息层级。 |
| 引用有效，但可能额外拼出失效图片地址 | 渲染的 Markdown 图片须对应选中且已交付的图片地址；错误由 Agent 修订为数字引用。代码、转义示例、纯输入转换以及混合任务中已绑定的用户 Markdown 地址得到保留。 |

`answer_retained_chars=8000`、`answer_retained_excerpt_chars=1000` 是默认工作集预算，可通过 `PI_AGENT_BUDGET` 配置。模型、推理状态、温度、总运行/工具/输出预算、旧模式、原文件和索引均未因本次审查扩大或重建。实验性行级检查仍默认关闭，默认计划功能使用独立开关。

## 保证范围及仍有的不足

结构性约束是通用的：已登记要求不能丢失，依据身份不能伪造，来源选择与原文记忆解耦，收尾和修订受原预算约束，已选来源须实际交付。它们不依赖具体作品或预期答案；新增控制也不只重复原选材任务。

这批样例没有证明任意未见任务的正确率。初次理解、合理分解、语义支持、观察准确性和最终文字质量仍依赖 Agent。比较答复中个别“该文未论述”的措辞超出局部阅读能证明的范围；配图答复仍额外给了备选，v5 也留下未定义的 `![说明][编号]` 字面标记。真实数字引用可以交付素材，但宿主不认证每一处自然语言或排版都准确。

未增加独立语义裁判，没有将 `completed` 等同于全文阅读或事实已核实。当前改进解决了可复现的任务偏置、证据/记忆耦合和修订资源问题；更多领域、复杂任务及供应商故障的成功率仍需要独立的更大样本评估。旧运行、知识数据和旧模式均保持原有边界。
