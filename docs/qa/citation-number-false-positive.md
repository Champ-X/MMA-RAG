# 普通数字被识别成引用（2026-09-27）

用户反馈 Harness System 历史回答显示“部分引用缺少来源数据”。直接读取对应会话 API 后，确认后端保存了 10 条来源，正文实际引用的 1、2、3、4、5、6、8、9、10 均有完整引用对象。

根因在 `MessageBubble` 的引用解析：规则同时接受圆括号数字和部分无括号数字，因此标题“近期进展（2026）”被当成来源 2026。缺失引用检查找不到该 ID 就报警，同时它也会占用连续显示编号。

改为共享 `lib/citations.ts` 解析规则，只识别明确引用括号 `[n]`，并兼容历史 `【n】`、`〔n〕`、`〖n〗`。圆括号年份、列表序号和普通数量保持原文。缺失来源检查仍然保留，包括真正写作 `[2026]` 的缺失引用。本次无需更改 Prompt、重生成历史回答或重启后端。
