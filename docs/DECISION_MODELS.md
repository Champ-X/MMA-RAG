# Decision 模型配置

「设置 → Decision 模型」只保留模型连接和两个常用功能：核对检索需求、检查回答引用。支持 TypeSafe Jev 直连、OpenRouter Decisions API 和阿里云百炼原生 Decision；原检索排序、查询改写与最终回答继续使用「模型与路由」中的配置。

## 选择、测试和保存

1. 选择服务商及判断模型。TypeSafe 使用服务端 `TYPESAFE_API_KEY`，OpenRouter 使用 `OPENROUTER_API_KEY`，百炼使用独立的 `BAILIAN_DECISION_API_KEY`；密钥不会发给浏览器或写入 Decision 配置文件。
2. 点击「测试连接」。它用固定的无敏感数据样例检查 Noul、Choice、Score 返回结构，包括当前流程使用的概率分布与置信字段。测试使用当前草稿，不保存设置，也不改变工作模式；测试通过不等于检索质量通过评估。
3. 按需开启「核对检索需求」「检查回答引用」，点击「保存设置」。设置对普通直搜和现有 Agent 的后续请求生效并在重启后保留。Pi 使用独立流程，不受这组开关控制。进行中的请求沿用开始时的配置。

页面使用一组带品牌图标的模型选择和两行开关，不再展示多层模式卡片、组合预设、重排实验、独立分类测试或逐条/批量实现选项。修改模型后清除旧连接测试结果；只有所选模型与当前保存模型不同，才显示当前使用的模型。「取消」重新读取保存值；关闭两个开关并保存即可停用。

测试连接和打开页面都不保存设置。若服务端仍保存旧版严格或重排实验配置，页面明确显示旧设置仍在生效，只有点击「应用简化设置」或保存修改后，才恢复常规排序并按两个开关运行；取消也不会迁移旧配置。新的引用检查统一使用批量方式，不让用户选择调用实现细节。

## 保留的两个功能

| 功能 | 开启后 | 关闭后 |
|---|---|---|
| 核对检索需求 | 原模型先规划，Decision 按需核对使用或排除哪些素材类型。只应用已通过用途验证的动作，无法确定时保留原规划 | 使用原意图模型，不增加需求核验调用 |
| 检查回答引用 | 对照引用文字，展示支持、冲突或依据不足的语句；仅作检查，不改写或认证答案 | 直接返回答案，不增加引用检查调用 |

两个功能默认关闭。需求核验以服务端返回的用途支持为准；当前通过这项验证的是 TypeSafe Jev 和 OpenRouter Luna Decisions。百炼等尚未通过的模型会禁用该开关并给出可选模型提示，引用检查仍可独立使用。切换到不支持的模型会在草稿中关闭需求核验，不隐式切回其他模型，也不会自动保存。引用诊断只是模型判断，尚未证明所有可选模型具有相同准确率。

本次没有把补证包装成默认增强功能：现有等候选配额对照尚未证明稳定优于原策略的简单扩充；旧重排评测也没有支持用 Decision 全面替换原排序。因此这些选项退出普通设置页，已有后端接口与冻结评测保留。独立意图诊断只保留 API，供开发排查使用。两项功能关闭后仍走原检索路径。

## 执行记录与兼容配置

回答底部的「Decision 记录」展示实际请求/响应模型、原规划、候选动作与是否生效、跳过/回退原因，以及引用诊断覆盖。支持、冲突、依据不足和未检查分开呈现；诊断不改写答案，也不认证整份答案。GET/POST SSE、非流式聊天和历史均保留结构化 `diagnostics`。

旧 API 仍兼容补证、重排和严格意图模式，用于读取已有配置和开发诊断；这些不是推荐的普通设置。保存简化设置将重排设为 `off`。严格模式失败会停止对应链路，不能把它等同于更高质量。此前补证和重排对照未证明稳定收益，因此默认关闭、退出普通设置页。

## 模型目录与兼容性

目录位于 `backend/app/core/llm/decision_catalog.py`，明确列出允许的请求模型及已观测的响应版本，拒绝未指定模型的静默替换。当前有 13 条路由：

- TypeSafe：`jev-1.13.0`。
- 阿里云百炼：`decision-model-preview`，使用原生 System One 接口。
- OpenRouter：`openai/gpt-6-luna-decisions`、`typesafe/jev-1.13`、`inception/mercury-decide:free`、`perplexity/pplx-decider-v1.1-27b`、`liquid/d1`、`cloudflare/clef`、`cloudflare/clef-flash`、`togethercomputer/tev1-4b-experimental`、`jaredpalmer/kev-4b`、`upstage/solar-decide-flash`、`upstage/solar-decide`。

OpenRouter 使用 `/api/alpha/decisions`，不是普通 Chat Completions。网关回退关闭；响应模型必须匹配所选模型或目录中的已知版本。上游更换版本时，先验证兼容性再更新目录。Respan Span-01 / Lite 目前仅接受特定 Noul 输入，无法满足统一的 Choice/Score 契约，暂不列入。

百炼默认使用北京试用入口 `https://trial.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/systemone`，也可通过 `BAILIAN_DECISION_ENDPOINT` 指向密钥对应地域的官方业务空间地址。界面显示入口类型和地域；不复用聊天的百炼密钥。百炼回执可能只有 `input_tokens`，未提供的输出用量或费用保持未知，Preview 未提供日期快照时不虚构版本。

百炼试用入口实测每次最多 16 个问题。客户端保留全部候选并按 16 项分批，所有分批共用原有 3 秒期限和整体预算；任一批失败不采用部分输出。20 项重排对应 16 + 4，回执记录实际批次。TypeSafe / OpenRouter 保持原单批行为，不因百炼限制缩小候选池。

客户端按服务商、模型、凭据和运行限制复用；切走再切回不重置该路由的预算和熔断。预算是每路由、每进程生命周期的输入 token 上限，不是整个账户的额度。保留 `JEV_TIMEOUT_S` 与 `JEV_MAX_INPUT_TOKENS` 环境变量。诊断区分请求模型、实际响应模型、路由及上游提供商；OpenRouter 采用上游报告费用，没有金额时标为未知，不套用 TypeSafe Jev 的价格。

## 旧配置和接口

- 原 `backend/data/jev_settings.json` 继续使用。缺少 `provider` / `model` 的旧文件按 TypeSafe `jev-1.13.0` 读取，不自动切换模型。
- 新接口为 `GET/PUT /api/decision/settings`、`POST /api/decision/test` 和 `POST /api/decision/diagnose-intent`；保留 `/api/jev` 同路径别名和内部 Jev 导入名称。独立诊断输入 `{provider, model, query}`，问题最多 4,000 字符；不会写入保存配置。
- 设置接口增加服务商密钥可用状态与模型目录，仅返回非敏感配置。
- 没有本地保存文件时使用 `DECISION_PROVIDER` / `DECISION_MODEL`；默认 TypeSafe Jev，OpenRouter 未指定模型时默认 Luna Decisions。`JEV_*_MODE` 和 `JEV_CITATION_STRATEGY` 继续兼容。
- 无效文件或无效环境模型会停用 Decision 并在配置接口显示可修复的错误；所选服务商缺少密钥时允许保存全部关闭，拒绝开启。
- 旧 Jev 专项评测显式固定 TypeSafe；新的检索评测记录生效的 Decision 配置，原生评测按该快照运行。历史评测产物不修改。

## 需求、覆盖和引用的新策略

自适应采用 `decision-plan-v3`：原生成式模型在正常任务分类、改写和拆解之外，提出至多六个来源动作，带当前用户原文连续片段、目标模态、全局/对象作用范围及 require/forbid。代码先验证出处、结构、调用价值与用途准入，再用一次 Choice 批次校验是否确实由当前请求蕴含；verified 必须满足当前响应模型版本及用途的已准入 profile 才应用；Jev require/forbid 门槛分别 .50/.70，Luna 分别 .55/.50。这次没有放宽门槛或修改已冻结的模型验证提示词。

原规划已明确开启的 require 不重复调用；相同动作和相同原话依据合并核验。forbid 即使原规划已关闭也继续核验并形成约束，防止后续文件绑定和 Agent 子查询重新开启。未通过用途准入的百炼来源动作在调用前跳过；其他模型返回未准入的实际版本时保留观察，不自动改变来源。对象级限制、无出处、相互冲突的全局提案不升级为全模态动作。每个动作分别采用，某个不确定项不阻止其他已核验动作；整体调用失败保留原规划。

启用路径的生成式提示词增加提案字段，不能声称其生成输出与关闭时逐字相同；关闭路径仍使用原提示词。Decision 不再给自适应路径重复判断任务类别/复杂度/所有模态来决定是否替代规划。严格意图仍保留 `v3.1` 前置独立判断及失败停止契约，仅供实验，不代表更高质量或更适合复杂问题。

自动直搜路由可在原有语义路由之后补充缺失的明确模态来源，总计至多 3 个知识库，不驱逐原目标；显式知识库/文件范围不会扩大。独立的背景依据需求成立时，已选库缺少文本索引且相应来源没有被排除，才可补充该库已有的媒体证据路径。此逻辑不依赖某部作品、关键词或具体题目。

覆盖记录区分未检索、未返回候选、候选被筛选、未进入上下文与已进入上下文。可用数量不是证据充分性，更不是正确率；生成器收到缺口说明，不能把本轮未搜索解释成全库没有。Agent 汇总以最终合并结果计算，历史记录使用生成上下文完成后的快照。

引用提取 v3 对同一句中单组引用核对完整语句，包含后续单位、条件、否定；多组不同位置的引用仍保守标为归属不明。媒体仅检查当前引用里已有的描述/转写，并显示“未核对原始媒体”；不自动下载原图、音频或视频。缺失、歧义、超时和没有可检查声明均单独显示，不能标为全部通过。旧提取器和补证 v1 保留为冻结评测入口。

## 开发与验证

协议实现位于 `backend/app/core/decision_providers.py`、`core/llm/jev.py`；来源动作核验位于 `modules/retrieval/processors/decision_plan.py`；引用诊断位于 `modules/generation/`。

`decision_plan_profiles.json` 按请求模型、实际响应版本、用途和验证提示词哈希绑定准入。紧凑的开发/保留集信号保存在 `evals/decision_plan_v2/`，独立保留集在 `evals/decision_plan_v2_holdout/`，由 `test_decision_profiles.py` 复算门槛与准入结论。它们是当前生产行为的溯源证据，不是所有模型的质量排名。

回归覆盖配置迁移、草稿测试不保存、错误脱敏、在途快照、预算复用、模型用途准入、失败/取消及诊断覆盖，运行方法见 [贡献指南](../CONTRIBUTING.md)。连接目录不保证每个地区和账户可用，使用前应测试实际选择。
