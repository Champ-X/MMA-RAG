# 图片与引用丢失回归修复（2026-09-23）

验证会话：`http://127.0.0.1:3001/chat/d6094a0a-3803-401f-8074-e675d6374bbc`。

## 原因

此前为让图片在流式正文中及时展示，将 StreamManager 的 citation 事件提前到了正文之前，但 GenerationService 仍按“当前已生成正文”筛选引用。此时正文为空，完整来源映射被过滤成空数组。前端和后端历史中的 `citations: []` 导致图片无法展示、编号点击无法找到来源。这是上次事件顺序修改引入的回归；不是本次会话的浏览器缓存问题。

此前测试仅检查事件顺序，且使用空引用映射，未覆盖完整链路中的数据丢失。原 README 和截图记录的是更早的不同会话，不能作为本次回归已经修复的证据。

## 修改

- GenerationService 原样透传预加载引用事件，保留完整证据编号及图片、文档元数据。前端依照正文实际使用的引用选择展示顺序，Jev 审计仍在正文完成后执行。
- 前端对当前消息的引用编号统一处理数字和字符串，缺失来源的编号禁用并给出说明，隐藏只有编号的无效来源按钮。
- 缺失来源的历史回答显示明确提示和“重新生成回答”入口。重新生成使用原问题及其文件范围，不消耗当前输入草稿；带附件的原问题不提供此快捷入口。保留历史回答，追加新回答。
- 点击引用阻止 Markdown 外层链接的默认导航及冒泡，避免跳离当前会话。

## 实际验证
