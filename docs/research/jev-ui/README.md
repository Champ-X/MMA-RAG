# Jev 页面配置与运行时切换

2026-09-23。设置页新增「Jev 语义判断」，分别控制意图快路径、重排 off/shadow/replace、引用诊断开关及 per_unit/batch_choice 策略。支持未保存提示、重新读取、全部关闭、保存状态和错误提示；未配置服务端密钥时禁止开启，仍可关闭已启用功能。

## 实现范围

- `GET/PUT /api/jev/settings`：严格枚举和完整配置校验，拒绝未知字段；只返回密钥是否已配置，不接收或返回密钥。
- `backend/data/jev_settings.json`：服务端原子写入，Git 忽略。保存成功后才返回新配置，写入失败保留原文件。文件不存在时使用环境变量；已有文件优先，读取错误或损坏时运行链路关闭 Jev，配置接口报告错误。
- 每个 HTTP 请求捕获不可变配置快照，覆盖普通和流式请求的整个生命周期。后续请求读取新值；多 worker 使用同一文件时无旧实例缓存问题。多副本需要共享配置文件。
- 意图和重排组件改为读取请求配置，保留独立实验使用的实例覆盖。共享 Jev 客户端不因开关切换重建，因此不会借切换重置额度。
- 密钥和超时/额度仍在服务端管理。保存模式不需要重启；更换密钥需要重启。

配置作用于当前服务的所有会话，与已有模型路由配置范围一致。此改动未新增账户权限体系，也未将诊断变成答案认证。历史实验和验证指纹保留原样，不能作为本次更新后代码的指纹。

2026-09-27 审查补修：独立评测入口 `jev_eval_server.py`（含 `evaluate_jev_system.py`）及 `verify_jev_generation.py` 已自动使用只读环境配置，忽略页面保存值，不读取或修改日常服务的 `jev_settings.json`。其他自行编写的脚本仍需显式隔离配置。以下 2026-09-23 的测试数量和真实调用记录保留为历史证据，最新检查见 [提交前审查](../review-2026-09-27.md)。

## 实际验证

通过正在运行的前端 `127.0.0.1:3001` 保存 adaptive / shadow / shadow / batch_choice，并验证刷新页面和后端重载后值仍保留。随后通过前端代理向实际 `/api/chat/message` 提交同一个问题：

> R200的额定功率是多少？请给出引用来源。

| 配置 | 实际结果 |
| --- | --- |
| 页面开启 Jev | HTTP 200；实际知识库检索、Kimi-K2.6 生成 `7.5 kW [1]`，1 条引用；批量 Jev 真实评估 1 单元，诊断约 0.513 秒、1,230 输入 token |
| 页面全部关闭并保存 | 同一道问题 HTTP 200，仍回答 `7.5 kW [1]`，1 条引用；响应不再包含 `jev_citation_audit` |

回执：[开启](results/live-enabled.json)、[关闭](results/live-disabled.json)。两次总耗时分别约 83.34 / 72.94 秒，存在原意图模型回退、模型调用和首次本地稀疏模型加载等影响；这不是速度对比实验，也不能由配置值推断意图和重排每个 Jev 调用都成功。引用诊断的实际成功有模型及用量回执。

页面验证包含缺少密钥时禁止开启、修改后的未保存提示、鼠标与键盘保存、刷新恢复、全部关闭，以及 390px 和桌面布局。390px 稳定布局下页面宽 390px，Jev 区域无横向溢出；操作按钮至少 48px 高。浏览器控制台未发现错误。首次对视口外按钮的自动点击未触发提交；将按钮移入视口后，鼠标点击与 Enter 均成功保存，并经接口确认。
