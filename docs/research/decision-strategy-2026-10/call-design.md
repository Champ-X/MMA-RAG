# Decision 调用调度与独立诊断

日期：2026-10-09。承接 [项目级重设计](project-redesign.md)，处理日常聊天误用严格分类器、无效重复调用，以及百炼原生批量上限。没有重建索引、重新解析材料或修改冻结的历史评测。

后续设置精简已将此报告中的独立诊断表单、组合预设及实验模式移出普通页面；接口与下面的历史验收记录保留。当前界面及旧配置保存行为以 [Decision 模型配置](../../DECISION_MODELS.md) 为准。

## 失败原因与职责

会话 `fbb3fe3d-12c1-4539-8552-d9b86ee6c4ac` 的问题是：

> 结合《浴血黑帮》这部电影剧情，为其挑选合适的海报封面和主题曲。

原保存配置为百炼 `decision-model-preview`，意图 `force`、重排 `shadow`、引用 `shadow/per_unit`。旧严格分类器要求任务类型、简单规划资格、每种模态的信号同时通过。某个信号处于灰区就以 `uncertain_decision` 停止整个请求，即使规划已经能识别海报和音乐需求。设置底部的严格勾选还会覆盖上方查询规划选择，使实际模式不明显。

原始失败发生在检索前，服务端没有保存成功消息。后续独立重放用于解释门槛，不能冒充当时的原始概率回执。这里没有降低旧分类器门槛或把“不确定”改成强行接受。

现在明确三个用途：

| 用途 | 调用与行为 |
|---|---|
| 日常规划后核验 | 原生成式规划先运行；仅对有作用、来源明确且用途准入的动作调用 Decision。不确定按动作保留原规划，调用失败也保留原规划 |
| 独立意图测试 | 只运行原生分类器，展示任务、规划与各模态信号和未通过条件。独立接口和表单，不检索、不生成、不保存设置 |
| 旧版严格模式 | 保留 API 和已有 force 配置的失败停止契约；已有配置在互斥项中明确展示，普通界面不再用隐藏勾选覆盖规划模式 |

来源动作与补证仍沿用用途准入及原文范围约束。百炼连通并不等于其来源动作已准入；此前独立语义评测未通过的 require/forbid 用途，在日常聊天中提前跳过。其重排与引用诊断仍按用户所选模式运行。

## 只调用能产生作用的判断

`decision-plan-v3` 沿用既有验证提示、模板 hash、模型版本和用途阈值，仅改执行调度：

1. 无提案、无可执行提案或已知未准入用途，在创建客户端前跳过。
2. 原规划已明确要求的模态，不重复核验 require。forbid 即使当前已关闭也继续核验，因为有效排除仍需约束后续文件绑定和 Agent 子查询。
3. 只有模态、动作、原话片段和目标描述都相同才合并；不同出处的动作不按模态粗暴折叠。
4. 至多六个动作进入一次原生 Choice 批次。每个动作独立采用；实际响应模型仍须再次匹配准入版本。
5. 回执记录 proposed/scheduled 数量、尝试调用次数及每项跳过原因，区分“未调用”“收到判断”“动作采用”和“实际改变规划”。

独立诊断接口 `POST /api/decision/diagnose-intent`（兼容 `/api/jev`）限制问题非空、最多 4,000 字符、一次批次、总计 3 秒。不确定与复杂度不足属于完成的诊断，不伪装成网络失败；传输错误仅返回脱敏类别。界面切换模型或编辑输入时取消旧结果展示，迟到结果不能覆盖新输入。后端未声明支持该接口时不显示入口。

## 百炼 16 问题上限与原子分批

完整管线和原会话重跑均出现过影子重排 HTTP 400。固定合成材料后，1 和 16 个问题返回 200；20 个问题返回：

```text
ValidationError: questions: 20 exceeds the limit of 16
```

普通英文问题和原电影问题的 20 项请求都失败，因此本次有直接的数量上限证据。当前官方文档把 16 写成建议值，实测北京试用入口按硬限制执行，不能用连接测试的三个问题推断生产批次可用。

原生客户端现在按供应商限制分批。百炼 20 个候选按 16 + 4 发送，保持问题 ID、共享 state、各题证据和提示不变；最多 64 个问题的应用总上限保持不变。TypeSafe 与 OpenRouter 保持原单批行为。

- 所有分批共用原有 3 秒总期限和一个并发槽，第二批不重新计时。
- 发送前一次性预留整组预算，计算重复 state 和每批协议开销，仍受 60KB 保守请求预算限制。
- 每批校验完整问题集合、原生输出、模型版本和用量，按 ID 合并；任一批失败立即停止，不返回部分分数、不截断候选、不重试。
- 只有整组成功才按真实 input_tokens 合计结算；失败/取消保留保守预留。可选费用或输出用量只有每批都报告才汇总，缺失保持未知。
- 成功的多批回执增加 `native_request_count` 和 `native_batch_sizes`。shadow 仍只记录对照、实际使用原排序；force 失败仍停止，未改变模式语义。

固定合成 20 候选经真实应用客户端得到全部 20 个分数，两次原生响应均 200，记录批次 `[16, 4]`。这是传输契约验证，不能据此声称分批提高准确率或不同批次分数已经校准。

## 真实调用与工程验证

本机完整回执根目录为 `ops/decision-session-fbb3fe3d-20261009/`；其中包含私有知识库内容，不纳入公开质量基准。紧凑协议和结果位于 [evals/decision_call_design_v1](../../../evals/decision_call_design_v1/)。

| 验证 | 结果与限制 |
|---|---|
| 4 个问题 × Jev、Luna、百炼 | 12/12 独立意图诊断完成；大多数不适合独立接管，完成不等于判断正确 |
| 相同原规划的动作调度 | 过滤前需 6 批，实际仅 2 批；Jev/Luna 的来源排除各一次批量应用三项动作，已满足音频需求及未准入用途零调用 |
| 原问题、纯文本问题 × 全关闭/当前辅助选项 | 4/4 完成生成；原问题开启组引用诊断覆盖 4/4、文本组 7/7；原问题影子重排 400 保留在原回执 |
| 原失败会话在第一次安全重启后重跑 | 成功完成，1260 字、4 条图片/音频引用；意图无提案、0 次 Decision 意图调用；该次历史中的影子重排 400 保留，不回填修复后的结果 |
| 百炼原生上限对照 | 1/16 项成功、20 项失败；独立修复验证完整获得 20 项，分批 16 + 4 |
| 分批修复后的额外完整管线 | 影子重排成功；但 Qwen 嵌入 12 秒超时使图片/音频召回均为空，只剩 15 项文本候选，最终回答证据不足。这次未触发多批，不能代替上面 20 项的真实分批验证，也不算电影选材目标完成 |
| 最终相关后端回归 | 741 passed，包括关闭路径、严格失败、分批原子性、预算、总超时、取消、会话恢复与各应用阶段 |
| 前端 | 220 项测试、3 项设置表单交互测试、TypeScript 与生产构建通过 |

原四次完整管线出现了嵌入失败、缓存和生成随机性，不能把开启组和关闭组的耗时、返回模态差异全归因于 Decision，也不能声称普遍检索质量提升。未删除旧失败或补填冻结结果。

## 当前服务与关闭路径

第一次加载时把保存的意图模式从 `force` 改为 `adaptive`，当时保留百炼及重排 `shadow`、引用 `shadow/per_unit`，并在原失败会话完成了一轮带 4 条媒体引用的回答。后续检查发现保存的供应商已切到 TypeSafe Jev（配置文件更新时间 22:18:07）；最终加载保留这一最新选择，没有切回百炼。当前为 TypeSafe `jev-1.13.0`、`adaptive/shadow/shadow/per_unit`。

与上一份历史报告不同，本轮通过项目启动器加载新版服务。重启前通过历史 API 导出会话，启动时显式恢复并核对；最后一次快照包含 1 个会话、2 条消息。这是可选的本地恢复入口，不是自动持久化或新的公共写接口。后续重启必须重新导出最新消息，不能复用第一次空会话快照。

全部关闭仍走原意图提示、原改写、召回、Qwen 排序与生成，不进入新调度或 Decision 原生客户端。没有改动用户的知识库范围、文件、索引或已有实验材料。启用 adaptive 的生成式提示会提出额外动作字段，因此不能承诺开启后的规划与关闭逐字相同。

本轮浏览器原生控制不可用（未发现可用应用/浏览器，native pipe 启动失败），所以只完成组件渲染/交互、构建及运行中 HTTP 验证，不声称完成新版视觉验收。此前版本的截图不作为本轮截图。
