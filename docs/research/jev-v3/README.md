# Jev 第三轮：引用支持关系诊断

> 本文保留第三轮结束时的状态。逐段归属和生成服务接入已在[第四轮](../jev-v4/README.md)继续实现、验证；跨轮结论见[总研究结论](../JEV-DECISIONS.md)。

2026-09-22。固定 `jev-1.13.0`，继续沿用 Qwen 重排和默认关闭的 Jev 意图实验配置。本轮新增一个独立可调用的引用诊断模块，**尚未接入在线生成服务，也不自动修改、拒绝或认证答案**。

## 为什么继续这个方向

第二轮独立留出实验否定了 Jev 替换 Qwen 和简单融合重排，但窄语义意图判断在合成系统样本中有改善。本轮探索另一种功能升级：引用编号有效以后，来源是否真正支持答案的事实。

项目 `ContextBuilder.validate_references()` 目前检查引用 ID 存在并组装引用元数据，不判断支持关系。这里的“编号存在”仅作为结构检查对照，**不意味着原系统声称存在的引用都是真实陈述**。

重新下载的[官方引用 cookbook](https://docs.typesafe.ai/cookbooks/citation_check)仍使用 `jev-1.12` 的 8 个 JWT 案例，其中 4 个错误是人工植入；其示例调用默认读取缓存，不是每次在线复现。示例按 confidence ≥0.8 让结果自动成立，本项目没有直接采用该策略。

同时刷新了[模型表](https://docs.typesafe.ai/models)、[confidence](https://docs.typesafe.ai/confidence)和[已知缺陷](https://docs.typesafe.ai/model-jaggedness/jev-1.13)。当前模型表仍列 `jev-1.13.0`；官方继续提醒数字精度、日期、间接推理、非英语和提示注入局限。4 份快照、抓取时间与哈希见 [sources.json](sources.json)。

## 冻结实验

[数据](../../../evals/jev_v3/citations/cases.jsonl)共 46 条，SHA256 `220081038284378bdfb2c009c46df6ca31d1d701fcc94d02bbe93868fb392b1c`：

- 36 条自编声明：12 个语义家族，每个家族包含支持、矛盾、证据不足三类。前 4 家族为开发集 12 条，后 8 家族留出 24 条，覆盖版本、实体、条件、复合声明、注入、资料未定、多来源和来源冲突。
- 6 条上一轮真实 Kimi 答案重放：保留完整答案和当轮引用映射，实际只向 Jev 发送答案中引用的来源。**这是整段答案对所引来源并集的检查，不是逐句引用归属验证；不是重新生成答案或重跑检索。**
- 4 条结构错误：不存在的引用、部分引用缺失、空来源、没有引用。确定性拒绝评估，不调用模型。

标签由本助手在调用前编写，未经过独立人工标注。开发集和留出集使用同一冻结提示词，没有看到结果后调阈值。`conflicting_sources-insufficient` 的标签专门表示“来源未解决冲突，不能确定唯一结论”，它与“至少一份来源否定声明”的语义有重叠，属于必须披露的标签边界。

[预先冻结的协议](protocol.json)比较两种信号，同一个请求包含三个问题：

1. **Choice**：支持 / 矛盾 / 证据不足。只有选择支持且其选中概率 ≥0.8 才发出支持信号。
2. **两个 Noul**：是否全部支持、是否明确矛盾；前者 ≥0.8 且后者 ≤0.2 才发出支持信号。

两个 Noul 是同一模型同次请求内的相关判断，不能当作独立验证者。阈值是本次固定实验规则，未进行生产校准。这里使用选中概率，未把 confidence 当作正确率。

## 实际结果

42 次真实 HTTP 全部成功，4 次结构错误均在调用前返回；模型响应版本与预算由现有 `JevClient` 校验。逐条原始概率、usage、时间、提示词/代码/数据哈希保存在 [citations.jsonl](results/citations.jsonl)，汇总见 [summary.json](results/summary.json)。

| 留出集 n=24 | 编号存在检查 | Choice 支持信号 | 两个 Noul 支持信号 |
| --- | ---: | ---: | ---: |
| 8 条正确声明发出支持信号 | 8 | 6 | 6 |
| 16 条错误或证据不足声明发出支持信号 | 16 | 0 | 0 |
| 正确声明支持召回 | 100% | 75% | 75% |

“编号存在检查”一列只表明结构检查无法区分语义错误，不是语义模型对照。Choice 三分类正确 **22/24**；两次错误把“2027版没有证据”和“来源冲突未解决”归为明确矛盾。两种支持门均漏过带注入文本的正确声明，以及正确描述两份来源存在分歧的声明。

开发集 Choice 三分类 12/12；门限后 Choice 接受 3/4 个正确声明，Noul 接受 4/4。留出没有显示 Noul 优于 Choice。不能因增加两个问题就声称更可靠，且本次测量是三题合并请求，**没有测量单独 Choice 或单独两个 Noul 的延迟和费用**。

6 条真实答案重放三分类和两种支持门均通过；全部为此前检查过的正确答案，因此这部分没有提供错误答案识别率证据。4 个结构错误均正确返回“未评估”。

42 次请求整体 P50 **0.695 秒**，P95 **0.840 秒**；留出 P50 **0.703 秒**，P95 **0.792 秒**。这些是单次小规模诊断请求耗时，不是在线完整回答时延或 SLA。服务端报告 32,401 输入 token，按公开价格估算 **$0.001360842**；没有查询或推断账户余额。

留出仅有 16 个负例，即使零误支持，也不足以证明低生产误放率；按独立二项样本假设，零错误的单侧 95% 上界仍约 17.1%，而这里家族相关使独立假设本身也偏强。因此保留诊断性质，不能用于自动放行或自动删证据。

## 实现、验证与复现

[`jev_citations.py`](../../../backend/app/modules/generation/jev_citations.py) 接收显式声明、引用 ID 和调用方已经授权的来源映射。只发送实际引用的来源；任意引用缺失时整项停止，不悄悄只检查剩余来源。空文本、超长声明和超大来源明确返回未评估，不截断。传输失败也是未评估；取消继续向上传播。预算、并发、模型与响应验证复用 `JevClient`。

该模块没有自动抽取原子声明或把句子关联到引用，不能把结果解释为“答案中每句话都有正确引用”。本轮不新增线上开关，调用方也不能把支持信号转换成已经验证的事实。

使用项目 Python 环境，离线复算不需要任何凭证：

```bash
python backend/scripts/build_jev_citation_dataset.py
python backend/scripts/evaluate_jev_citations.py

# 新的付费调用写到新路径，保留本轮原始证据
python backend/scripts/evaluate_jev_citations.py --live \
  --provider-env "$PROVIDER_ENV" --key-file "$KEY_FILE" \
  --output /tmp/jev-citations-new.jsonl --report /tmp/jev-citations-new.json
```

默认累计输入预算 200,000 token，失败即停止后续付费样本，不自动重试；已有未解决失败拒绝自动续跑。同一收据续跑必须匹配数据、提示词和诊断模块代码哈希。生产配置导入要求 provider 配置；离线复算不导入项目运行时。

Jev 相关合同与回归测试本轮 **44 passed**，包括 6 个新引用测试；测试覆盖来源隔离、缺失来源、输入上限、冲突信号、传输失败和取消。测试最初因本工作树没有 `.env`、缺少必填 `SILICONFLOW_API_KEY` 而在收集阶段停止，随后在纯离线测试环境提供占位配置通过；占位值未用于真实 provider 调用。真实 Jev 使用已有本机凭证，未写入源码或回执。验证记录见 [verification.json](results/verification.json)。

## 接下来仍需完成

当前更值得继续的是“逐句/原子声明与引用对应关系”及影子诊断接入：整段答案对来源并集通过，仍可能把事实归到错误引用。需要加入真实答案的错引、漏引与数字/单位变异对照，并验证流式完成、取消和尾延迟后，才能判断是否适合线上可选诊断。真实业务标注、跨时间重复实验和更强语义基线也尚未完成。

本轮形成了新的可运行方案和真实调用证据，没有证明自动引用认证可用。总研究目标继续保持 active；改动未提交、未部署。
