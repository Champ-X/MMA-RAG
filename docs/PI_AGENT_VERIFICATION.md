## 旧模式并发隔离

真实协议固定同一问题，三个旧模式并发执行，并比较无 Pi / 两个 Pi 任务两种条件，先预热，再按 ABBA 次序进行。检查答案存在、引用预期论文、无流错误。预设延迟审查门槛为负载/对照中位数比不高于 1.25。

## 跨问题与在途模型检查

先冻结 `quality-cases-v1.json`（SHA-256 `3f14104447cf9d02468458faa5be9862fda7decd383279cf665645fb0dc8aa6b`），覆盖七层分类、AHE 三种可观测性、数字与百分点、跨论文比较、指定文件范围及无答案六题。参考事实来自已保存的实际原文，并保留来源版本及正文哈希。每题运行三个旧模式的对照/负载条件，再运行 Pi，共 42 份回答记录，保存为 `quality-v1/`。

负载条件先等待两路 Pi 的 `model.started`。12 次 Pi 主模型调用均与旧 SSE 窗口实际重叠，耗时约 0.63–1.57 秒；后续研究调用继续服从旧请求优先级。36 条旧模式响应没有流错误，引用编号均能匹配返回来源，指定文件题没有越界。

内容审阅发现：可回答题的关键数字及分类没有新矛盾，但旧模式在框架运行时取舍题的两种条件下都遗漏了镜像体积和启动延迟；跨论文题的 Direct 负载答案也更简略。无答案题的 Auto 与旧 Agent 负载答案附了无关来源，而各自对照未附。**因此预设的严格实时配对质量门槛没有全部通过。** 相同生成文本经 `bf9627b` 的引用选择器重放，仍保留完全相同的引用；旧检索、生成、Agent 和模型管理模块与基线无差异，见 `legacy-no-evidence-baseline-replay.json`。这确认既有引用合同的缺陷，不能据此证明随机生成质量的统计非劣效性。

## 原始基线与候选的完整流程回放

使用原始 `bf9627b` 的独立检出，保留相同运行配置，从真实模型、Qdrant 和 MinIO 录制响应。沿用上述六题，再加入含 emoji/换行的 `@` 对照材料与独立文件范围，以及同轮图片、5 秒音频、5 秒视频附件；每题运行 Auto、Direct、旧 Agent，共 24 个案例。未替换意图理解、查询改写、本地编码、路由、检索、重排、旧 Agent 规划、生成、引用选择或历史写入。

首轮 `replay-v1-*` 的基线自回放和候选回放均得到 24/24 相同的答案与 SSE 引用，但完整请求门槛失败：三次目录缓存刷新因 60 秒 TTL 与加速回放的时钟不同而未发生，另有六次视频 sparse 请求受到旧关键词 `list(set(...))[:10]` 的进程随机顺序影响。两组都有 1,287 个未消费响应、6 次未记录请求；这些请求被拒绝，未回落到真实网络。保留首轮响应、结果和脚本，不能将“答案一样”误报为完整检索一致。

## 明确限长与自主起草目标的区分

Flash 原 q6 主动登记了 2000 字上限，宿主没有自动补值。现有 schema、Pi 校验和宿主都支持合法的双 `null`；问题不能归结为接口不接受无限长。实验系统提示此前强调“有明确篇幅限制不能填 null”，无限制时的行为仅写在字段说明里。现在补齐两种情况：有明确字符上限则登记原值与限长原句，没有则两项同时为 `null`；自主起草目标、事实数字和输出预算不能当作用户限长，风格与非字符计量要求保留在必答要点中。

修改仅涉及实验提示的一段要求说明，不改变工具 schema、宿主判定、冻结题目/参考、预算、默认 Pi 提示或旧模式。`requirements-null-guidance-v1/` 保存修改前快照、原 q6 失败哈希与检查结果：运行时 **56 项通过**，要求登记与反馈后端 **49 项通过**。这些原有检查覆盖协议和合法 null 的处理，没有为提示文字添加镜像测试，也不把测试通过解释为真实模型改正了要求理解。尚需另立冻结计划，用原有限长题和原无限长题各运行一次 Flash；此前失败不作修复后重评分。
