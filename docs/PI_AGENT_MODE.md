# Pi Agent 模式

Pi 使用 [Pi Agent SDK](https://github.com/earendil-works/pi) 的实际循环完成规划、工具选择与最终生成。Tessmora 的 Python 宿主负责范围校验、工具执行、进程监督、事件持久化和证据身份检查。常规 `direct / auto / agent` 与 Decision 配置不参与 Pi 编排。

## 使用与生命周期

1. 按 [快速开始](../README.md#快速开始) 安装 Node ≥22.19 及 `agent-runtime` 依赖。
2. 打开输入框的 `π` 开关，选择允许的模型；知识库/文件选择器限定搜索范围。
3. `@` 文件与本机附件作为阅读材料，不自动扩大搜索范围。展开过程可查看真实工具参数、证据、耗时与错误。
4. 点击停止可取消运行。浏览器断线不取消后台任务；刷新后从服务端账本恢复事件和证据。
5. 删除会话会先停止本地对话流、阻止待提交任务继续创建，并回收尚未发布的新附件；服务端停止该会话的 Pi 运行中、排队任务，以及其他标签页或客户端发起的普通模式请求（含附件摘要），等待清理后再移除本地会话。失败或超时会保留会话并允许重试；持久关闭标记阻止延迟上传或重试重新创建任务。Pi 模式关闭后仍可执行此清理，访问身份校验保持有效。此联动基于当前单实例、单可信工作区部署。

任务在来源准备之前即取得运行 ID；准备期间也可以取消。宿主完成来源身份与范围校验后才启动工作进程。服务重启把未完成运行标为中断，不自动重试模型请求；继续提问创建关联的新运行。

同一会话可以切换模式。普通模式仅接收按预算裁剪的正式对话文本，不将 Pi 工具结果或草稿冒充新检索结果。后台运行不占用其他会话的停止按钮。

## 执行与权限边界

```mermaid
flowchart LR
  Web[Web] --> API[/api/pi]
  API --> Host[Python 宿主与 SQLite 账本]
  Host <--> Node[单任务 Pi Node 进程]
  Host --> Tools[只读来源工具]
  Tools --> Data[MinIO / Qdrant]
  Host --> Events[持久事件与证据]
  Events --> Web
```

工具没有任意 Shell、代码执行、网络抓取或自动发现的扩展权限。来源按知识库和文件身份绑定，跨库 parent 关系、歧义身份和越界来源被拒绝。目录不是已读证据，文件名也不是授权凭据。

默认是本机单用户工作区。服务端 `ALLOWED_KB_IDS` 限制可访问知识库；远程调用需要配置 Pi token 与可信身份。这不替代整个应用的认证和多租户 ACL，参见 [安全说明](../SECURITY.md)。

## 工具

| 工具 | 能力与返回边界 |
| --- | --- |
| `update_answer_plan`（默认开启） | 按 ID 合并变化字段，保留省略字段及未提交项。每项的 `items[].research_state` 记录候选、已核实条件、未解问题和下一次观察目标；解释修订须给出 `revision_reason`，用户原句不可改写。计划用于研究组织，不是最终引用清单。 |
| `list_sources` | 按名称及可选模态过滤后分页列出可读来源，区别输入材料和可搜索文件；目录本身不是证据。 |
| `search` | 精确短语匹配，或独立语义向量与词面匹配融合；覆盖文本及媒体描述/转写。`result_unit=source` 按不同来源返回代表片段，适合筛选素材；默认 `passage` 保留片段粒度。`source_ids` 只收窄当前检索范围，不隐藏服务失败或截断。 |
| `read_source` | 默认 `view=content` 分页读取解析后的文档 chunk 或媒体索引记录，长片段支持按字符位置续读并校验原记录版本。`view=overview` 提供每条最多 400 字符的索引原文预览、续读导航和同来源已有直接观察，不代表通读或重新观察媒体。 |
| `expand_context` | 读取已返回文档证据的相邻 chunk。 |
| `recall_evidence` | 恢复已归档的工具证据，保留原编号。 |
| `inspect_media` | 显式选择 `visual/audio/both`；图片/PDF 页仅视觉、音频仅声音，视频可分别提供通道问题。默认 30 秒，长区间逐包保存，每包至多采样 6 帧；运行内精确请求复用，失败保留已完成包，重试仅执行缺失包。可用 `requirement_id` 和 `observation_goal` 关联待核实条件。 |
| `query_table` | 对 CSV/TSV/XLSX 进行确定性的过滤、分组、计数和数值计算；保留行号与计算范围，不执行公式。PDF 表格通过原文和页图核对。 |
| `set_answer_requirements`（实验开关开启时） | 研究前登记 Pi 理解的正文上限、对应用户原句和必答要点。宿主核对原句身份，将要求与过程事件一起持久化；本轮不可通过后续工具调用改写。登记前可以请求澄清。 |
| `check_answer`（实验开关开启时） | 可选的草稿检查：返回正文/限制说明编号、实际字符数、缺失的声明和选中的原文。检查不结束任务，不调用模型或取得新证据。 |
| `submit_answer` | 接受 Pi 写出的最终回答，检查实际返回的引用编号与正文一致。实验开关开启时另查正文单元和原文片段绑定。用户要求确实未交付才使用 `partial` 并列出对应缺口；一般来源说明不降级状态。没有相关依据时使用 `outcome=not_found`、`partial` 和空引用。 |
| `ask_user` | 结束当前任务并提出澄清问题，保留已有过程。 |

检索摘要、解析文本、转写、媒体模型观察和表格计算具有不同的证据含义。引用校验能证明编号与返回内容的身份一致，不能证明每句话与来源语义蕴含。视频离散采样不能作为全片逐帧观察的证明。

## 原文与媒体契约

`read_source.next_start` 继续读取索引片段；`text_continuations` 继续读取同一片段尚未交付的字符区间，携带记录版本，拒绝跨版本拼接。`search.source_ids` 仅收窄当前搜索，不能让只读输入材料进入检索范围。图片可返回已校验的父文档导航，但链接不代表已经阅读父文档。

媒体观察保留绝对时间、采样区间和来源身份。相同原文件的多条证据保留独立编号，正文媒体按来源及时间区间去重。视频离散采样不等于逐帧核验。附件原件保存在 Pi 本地数据目录，可随历史预览。

媒体缓存仅在一次运行内有效，按来源版本、区间/页码、通道、实际问题、模型、语言及提示词/采样版本精确匹配；不会把语义相近的问题视作相同观察。相同在途请求共享工作，一个等待者取消不取消其他等待者。最后一个等待者取消或运行结束时回收共享请求和临时文件。模型返回的每个成功片段立即存入账本；后续失败返回明确的 `coverage=partial` 与成功证据，取消只保留审计记录，不把尚未交付的证据变为可引用材料。

模型使用的证据包保留完整已交付文本、来源版本、观察类型、位置、截断及续读边界；展示配置和完整调用审计单独存储。这里不摘要或截断证据正文。当前计划已有的原文不再在历史计划结果中重复发送，仍保留工具配对与证据导航，且可以复读原文。

## 回答计划与交付

默认开启 `update_answer_plan`。Agent 将交付项绑定用户原句，区别外部来源任务和纯输入转换任务；研究中可追加遗漏要求并保留所选原文区间。计划与证据选择持久化，不等于最终引用清单。

更新只需 ID 和变化字段，省略的交付项、单项字段及研究状态字段都保留原样；数组用 `[]` 明确清空。新项必须提供 `requirement` 和 `quote`，宿主先合并为完整项，再执行原有证据、类型及原句验证。用户原句保持不变；纠正 `requirement/modality/basis` 时须填写修订原因，旧解释和变更记录保留审计。`research_state` 是 Agent 的工作判断，宿主不把其中的“已核实”当成独立事实证明。

研究优先从索引筛选候选，再针对影响结论的缺口观察原材料。连续三批研究未改变计划时，下一次已有模型请求加入状态复核提醒；不额外调用模型、不关闭研究工具，也不以“最终未引用”作为提前停止依据。用户明确要求穷尽、比较或存在关键反证时仍可继续扩展。

- `pending`：继续研究。
- `ready`：已有交付依据。
- `incomplete` / `unavailable`：有明确未完成要求，必须保留相应缺口并提交 `partial`。
- 全部就绪时提交 `completed`；没有相关来源时使用 `not_found` 与空引用。

宿主检查计划状态、缺口、输入身份和引用编号的一致性，不替 Agent 改写答案。一般来源说明不自动构成未完成要求。纯输入转换可无引用；外部研究不能通过改写任务类型绕过证据要求。最终引用只使用本次已取得的证据，图片地址也须有合法来源或来自用户输入。

这些约束不证明 Agent 完整理解了所有自然语言要求，也不证明每句话被来源蕴含。最终事实、比较完整性和正确拒答仍需人工核对。

## 配置与资源

在 `backend/.env` 中设置，以下所有选项加前缀 `PI_AGENT_`。配置实现见 [`config.py`](../backend/app/modules/pi_agent/config.py)。

| 选项 | 默认值/用途 |
| --- | --- |
| `ENABLED` | `true` |
| `MODEL` | `deepseek:deepseek-flash` |
| `THINKING_ENABLED` | `false`；可独立开启 Pi 主模型推理。当前适配 DeepSeek/Qwen 的推理协议；其他未配置推理协议的模型会明确拒绝开启。 |
| `ANSWER_CHECKS_ENABLED` | `false`；实验性的正文单元/来源绑定与声明式篇幅检查。当前实测候选未通过，不建议作为默认开启。 |
| `ANSWER_PLAN_ENABLED` | `true`；Agent 登记交付项、保留已选证据，并在提交时检查完成状态、缺口及引用身份；设为 `false` 可回到此前的提交协议。 |
| `MODEL_API_KEY` / `MODEL_BASE_URL` | 可选的 Pi 主模型专用凭证和端点，避免共用服务商配额；不写入账本。 |
| `EMBEDDING_MODEL` | 必须匹配已有索引的向量空间。 |
| `VISION_MODEL` | `aliyun_bailian:qwen3.8-flash` |
| `AUDIO_MODEL` | `aliyun_bailian:qwen3.8-omni-flash` |
| `ALLOWED_MODELS` | 可选 JSON 模型列表，未设置时仅开放 `MODEL`。额外模型须先验证工具调用支持；如设置列表，应包含默认模型。不会自动开放旧模式的整个模型目录。 |
| `ALLOWED_KB_IDS` | 可选 JSON 知识库列表；空列表表示无知识库访问权。 |
| `API_TOKEN` / `TRUSTED_USER_ID` | 远程 API 的服务端凭证与可信工作区身份。默认仅本机访问。 |
| `MAX_CONCURRENT_RUNS` | `2`；调度并发，额外任务排队等待且可取消。 |
| `MAX_CONCURRENT_SEARCHES` | `1` |
| `MAX_CONCURRENT_MEDIA` | `2`；每个运行的本地媒体读取/解码并发。同时使用独立的同容量观察准备槽，限制解码后等待模型的媒体负载数；远程模型等待不占本地解码槽位。 |
| `MAX_CONCURRENT_PROVIDER_REQUESTS` | `2`；单宿主内各 Pi 运行按供应商共享的模型并发，供应商之间互不占用容量。普通模式未接入此容量池。 |
| `YIELD_TO_LEGACY` | `true`；目录读取和索引检索准入给普通请求有限优先等待，等待发生在取得检索槽位之前。主模型与一般工具不再等待整个普通 HTTP 请求结束。 |
| `LEGACY_PRIORITY_GRACE_SECONDS` | `1.0`；每次索引检索准入的最长优先等待；一次目录扫描共享同一老化窗口，分页不重置等待。之后允许 Pi 继续。不是整个任务时限；等待/恢复事件记录资源、时长及 `aged/idle` 原因。 |
| `DATA_DIR` | `data/pi-agent`，包含 SQLite 账本、私有附件和预览。单目录仅一个宿主进程持锁。 |

没有应用层累计 Token、总时长和工具次数上限。用户可取消；模型上下文、服务商容量和机器资源仍限制运行。并发参数控制调度容量，超过容量的任务等待且可取消，不是单任务预算。

为避免无进展的自动调用持续计费，运行时会停止以下情况，并保留过程、证据与用量：

- 同一工具、参数及错误类型的不可重试拒绝累计 3 轮，即使夹带其他成功操作也会停止；该操作真正成功后清除对应历史。可重试错误只在没有新结果时累计，同样失败 3 轮或工具失败累计达到 8 轮会停止。已存证且实际返回的新 partial 片段只重置可重试失败，不清除不可重试历史。
- 相同工具操作及有效返回结果重复 3 轮，没有产生新结果；证据编号、展示字段或供应商 usage 变化不算新证据，原文、来源版本或观察区间变化仍算进展。经宿主存证并实际返回的新 partial 片段也计入进展，重复 partial 不会绕过检查。
- 首次只返回文本、未调用工具或正式提交后，下一次已有模型请求使用 `tool_choice=required`，仍可调用检索、澄清或提交等全部工具。有工具调用后恢复默认；DeepSeek 开启推理时不支持该选项，保留用户推理设置并沿用文字提醒。连续 3 轮仍只返回文本则停止。模型输出因长度被截断时立即停止自动续跑。
- 上下文归档后仍缺少有效输出空间，在发出下一次模型请求前停止，避免退化为反复购买 1 Token 输出。
- 主模型连接或响应流连续 120 秒没有数据；辅助模型连接的读取空闲超时同为 120 秒。持续返回数据的长请求不受此空闲超时限制。

这些检查不限制持续取得新结果的正常长任务，也不保证能识别所有语义上的无效研究。已经发往供应商的请求可能已产生费用，取消不能撤回已计费用量。删除会话仅移除浏览器会话与本地消息附件，服务端账本、证据及私有附件仍按现有历史保留策略留存。

上下文归档保留工具调用/返回配对、用户要求与证据定位，原始产物仍可复读。`UsageLedger` 记录供应商实际用量；取消或异常退出时尚未收到回执的请求也标为用量未知，不将其当作零消耗。推理开关只影响 Pi 主模型，过程事件不公开原始思维链。

`ANSWER_CHECKS_ENABLED` 是默认关闭的实验性正文单元与来源片段绑定；未证明可普遍改善答案质量。它与默认开启的回答计划是不同开关。单个数据目录只允许一个宿主持锁；SQLite、附件、模型凭证与运行产物均不提交 Git。

每次运行记录代码、系统提示词、工具契约、配置和输入的指纹，记录模型准入/首次有效内容/完成耗时与输入字节数。字节数不是 Token 用量；实际用量以服务商回执为准。指纹不保存密钥或端点。索引仍是独立的词面与稠密检索，尚未引入原生 CLIP/CLAP、多分支并行或跨运行媒体缓存；`result_unit=source` 不保证穷尽所有可用来源。

## 验证与源码

- 宿主与工具：`backend/app/modules/pi_agent/`，回归：`backend/tests/test_pi_agent_*.py`。
- Pi 循环与协议：`agent-runtime/src/`，回归：`npm --prefix agent-runtime test`。
- 前端事件恢复与媒体展示：`frontend/src/hooks/usePiAgent.ts`、`frontend/src/lib/pi*.ts`。

真实模型验证应固定来源和问题，核对答案、引用、媒体预览、取消与刷新恢复；额外进行常规路径并发对照。运行回执留在忽略目录，不能用一次成功或单个延迟样本代替质量与性能保证。更多命令见 [贡献指南](../CONTRIBUTING.md)。
