# 行内文件引用与本机附件

输入框使用 Tiptap 的原子节点承载引用，保留编辑器的光标、撤销、选区和中文输入行为。编辑器按需加载。图片显示缩略图；音频显示封面（若有）或音乐标识。知识库引用使用实线与空间名，本机附件使用绿色虚线与“本机”标签。

## 交互约定

- `分析这张图@空间/文件` 不要求在 `@` 前加入空格；邮箱不触发菜单。
- `@本机/文件` 与 `@附件/文件` 搜索本轮上传，菜单与知识库文件分组。
- 同一文件可以重复引用；各处独立删除，引用材料按文件去重。
- 附件卡片上的 `@` 在光标处插入引用。移除上传附件会同时移除它的行内引用，并重置编辑历史，避免撤销恢复悬空附件。
- `@` 知识库引用是用于理解和比较的输入材料，不会自动限定检索范围。“指定检索文件”单独设置强制范围，取消范围不会删除行内引用；同一文件可以同时作为引用材料和明确选择的范围。
- Enter 发送，Shift+Enter 换行；候选菜单支持方向键、Enter/Tab 和 Escape。组合输入期间不发送。
- 粘贴只接收纯文本，不接受外部 HTML 构造的文件身份；复制到纯文本时保留 `@文件名`，需要重新选择才成为绑定引用。
- 每条用户消息在鼠标悬浮或操作按钮获得键盘焦点时显示复制、编辑按钮。复制完整原文（含换行及 `@文件名`），剪贴板被拒绝时明确提示，不能假报成功。
- 编辑恢复到输入框，修改后作为新一轮重新检索生成，保留原对话。输入框已有草稿时暂存，取消编辑或提交成功后恢复；切换编辑对象仍保留最初的草稿。请求进行中禁用编辑。
- 编辑恢复原始附件二进制，为本轮生成新附件 ID 并重绑所有出现位置；缺少原文件时保持草稿不变并提示重新添加，不用缩略图或摘要代替原件。旧消息中混入范围的行内文件会迁移为引用；新消息保存 `scope_version=2`，明确选择的范围完整保留，包括与引用重叠的文件。
- 消息附件仅展示缩略图或播放器，不再在下方重复显示“本机 · 已解析”等文字；消息正文也不再另列知识库文件路径。

## 提交契约

`message` 是包含 `@文件名` 的纯文本；`mentions` 独立保留各次出现的位置：

```json
{
  "source": "attachment",
  "attachmentId": "upload-id",
  "name": "山水.png",
  "type": "image/png",
  "start": 2,
  "end": 9
}
```

`start/end` 是 **相对于完整 message 的 UTF-16 code unit 偏移**，end 不包含在区间中，与浏览器字符串一致。知识库引用使用 `source=knowledge`、`kbId`、`fileId`、`kbName`；multipart 的 `attachmentIds` 与文件上传顺序一一对应。预览 URL 不进入提交或持久化的引用数据。

multipart 同时传 `messageJson=JSON.stringify(message)`，服务端以解码后的原文为准。浏览器会将普通表单字符串中的 LF 换行改为 CRLF，直接使用普通 `message` 字段会使第二行起的引用偏移失效。JSON 转义保留原始换行、空行、前导空格和 Unicode 字符；旧客户端只在原文校验失败、且还原 LF 后所有位置与身份均通过校验时兼容恢复，不按文件名猜测新位置。

`referenceFiles` 独立提交行内知识库文件，以知识库 ID 与文件 ID 去重；`selectedFiles` 只提交明确选择的文件范围，`knowledgeBaseIds` 只代表用户选择的知识库范围。新客户端始终发送 `referenceFiles`（没有引用时为 `[]`），用于与旧版合并字段区分。旧请求依据已校验的行内引用拆分合并字段；旧前端由合并文件自动推导的知识库 ID 同步解除，独立选择的文件继续限制搜索。

后端检查位置、名称、重叠、来源、引用文件清单及上传标识；过期或伪造的引用在模型调用前失败。不能仅按文件名匹配。同名文件与重复引用使用稳定身份区分。

请求校验失败以 `stage=validation` 返回，附件解析失败以 `stage=attachment` 返回；界面区分这些失败与模型生成失败，同一错误只显示一次。失败消息提供“编辑后重试”，从浏览器附件存储恢复原文与上传文件，重新建立本轮附件标识；浏览器已清理原文件时明确提示重新添加。

Direct 与 Agent 均收到在原句位置标记的对象和来源映射。先按各引用自身的知识库/文件身份读取已有解析内容，再用于理解问题和改写检索词；引用材料保留到最终生成，避免检索其他图片、视频时丢失作为比较对象的音频。读取引用不伪造语义匹配分数。检索继续受独立的 `selected_files` 和手动知识库选择约束；仅有行内引用时仍允许智能路由到其他知识库。Agent 子查询沿用这份独立范围，输入材料不冒充新找到的推荐结果。本机附件不会被当作知识库筛选条件。本轮成功解析的附件分配正式材料编号，与知识库引用统一使用 `[n]`，并保留独立来源。

Direct 的智能路由也接收明确的图片/音频/视频需求。若语义相关度最高的库缺少所需媒体，结合已有索引统计为相关媒体库保留检索位置，避免曲名让“找匹配图片和视频”的问题只搜索音乐库；保留语义首选库、相关性门槛和目标库数量上限，不填满所有位置，也不改写手动指定的范围。新增库仍显示其真实相对画像得分。

## 回答中的附件与引用

- 只有状态为 `ready` 且有解析内容的附件进入生成引用表。编号在知识库候选后顺延，A/K 身份标签不会当成引用编号。失败附件不成为回答证据。
- SSE 与历史引用携带 `source=attachment`、`attachment_id`、原文件名、解析内容及实测信息。附件没有知识库路径、检索分数或预签名 URL；这些字段不能伪造。
- 正文实际使用 `[n]` 时，就地展示原图、音频或视频播放器；同一附件多次引用仅在首次出现处展开。完成时仍按正文过滤来源，未采用的附件不自动塞入回答。
- 段落、标题、列表、表格使用同一引用编号映射。表头与单元格中的引用可点击，首次在表格出现的媒体放在整个表格下方；列表中的媒体保留在所属列表项内，嵌套结构不会重复展开。代码和链接里的数字不作为媒体引用。
- 本机媒体及引用以绿色虚线/“本机”区分。点击角标或卡片名称打开原附件与解析依据；不展示知识库检查器。仅按稳定附件 ID 从浏览器存储恢复，不能通过同名文件猜测来源。
- 刷新后仍可恢复媒体；若原文件已清理，图片可显示保存的缩略图并说明，音视频显示无法预览的提示，引用的解析内容保留。临时 Blob URL 不写入引用或历史。

## 附件解析

- 每轮最多 3 个附件，图片/音频每个 10 MiB；新增 MP4、WebM、MOV 短视频，每个 30 MiB 且不超过 60 秒。服务端有限读取、媒体头检查，并用 Pillow / ffprobe 核验真实音轨、画面及实际时长；较长视频继续走知识库解析。
- 视频最多抽取 6 个带时间点的画面供视觉模型分析，并提取单声道音轨解析；保留实际采样时间和音轨解析状态。音轨失败会明确说明，不能推断其声音；画面解析失败不作为可引用证据。抽样观察不等同于逐帧理解。
- 图片读取尺寸；音频读取时长、采样率、声道数，并按实际容器确定模型输入格式。依赖项目已有 Pillow、FFmpeg/ffprobe。
- 并发解析，每项 120 秒超时，各自返回 ready/failed。单项失败不抹去成功项；全部失败结束请求，不继续用失败文本生成答案。
- 针对问题保留视觉特征、语音事实、音乐音色和结构等信息；通常请求 200–600 字，密集信息最多 1500 字，代码上限为每项 1800 字。各项独立限额，不再用 900 字总截断吞掉后面的文件。
- 本地实测信息优先于模型推断；明显超出实际时长的音频时间描述判为失败。该校验**不等于**音乐语义、乐器、音高或画面细节的正确性认证；模型观察仍可能不准确。
- 生成上下文压缩保留引用映射与附件证据，且保留音频/视频类型。附件不写 MinIO/Qdrant、不重新解析现有知识库。
- 历史保存引用、附件身份、解析状态、实测信息和摘要；后续轮次在现有历史字符预算内使用记录。原始附件仍在浏览器 IndexedDB，服务端不持久保存原始二进制；摘要不能替代完整原件或无限多轮记忆。
- 流式请求中断且没有结束事件时显示错误，不让输入框一直等待。


回归覆盖 Unicode 偏移、同名和重复引用、移除附件、传输契约、流异常、Direct/Agent 数据贯通、部分/全部失败、上传大小限制、解析超时、真实 WAV 时长和错误时间描述；语音内容中的钟表时间不作为媒体时间戳校验。

传输回归使用 Fetch `Request` 的真实 multipart 编码再解析请求体，覆盖多行、空行、表情和混合引用，而非仅查看内存中的 `FormData.get()`。后端覆盖新 JSON 请求、旧浏览器 CRLF 请求及本身使用 CRLF 偏移的客户端。
