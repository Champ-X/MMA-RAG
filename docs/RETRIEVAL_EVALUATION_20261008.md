# 2026-10-08 检索评估结果与下一步

本轮完成了 **300 道公开题 + 80 道本地题**的多方案对照，共保存 **1,740 条正式/控制运行任务记录**，包括失败和冷却拒绝。主要结论是：应优先扩大独立来源和经过复核的证据真值；算法优化则按排序、证据缺失和运行故障分别推进。题量增加本身不能修正不可靠标签或不可比的统计口径。

机器可读汇总与成对区间见 [results-20261008-v2](../evals/retrieval_v2/results-20261008-v2/summary.json)，复现方法见 [检索评测 v2](RETRIEVAL_EVALUATION_V2.md)。原始回执、私有标注和逐题证据位于仓库根目录的 `data/retrieval-evaluation-20261008/`，保持 Git 忽略。

## 本轮补齐了什么

- 从 7 份合成文档、8 道快速回归题，扩展到公开完整语料与真实多模态索引。v1 基线继续保留。
- 将“找到了正确文件”和“找齐了必需段落/时间片段”分开评分；支持多证据 AND、有效替代证据 OR、未知标签和有范围的无答案题。
- 增加来源/配置哈希、逐题追加回执、进程锁、未确认调用保护、模型用量缺口、范围检查和配对集群 bootstrap。
- 实际运行 BM25、Dense、Hybrid、Hybrid+重排，以及现有 Direct、旧 Agent 和 Pi。Agent 结果来自其真实执行，没有替换成独立 Direct 搜索。
- 修复评测适配器对 PDF 图片父文档别名的处理；基于原始 Pi 回执离线复算，没有重新调用模型或修改标签。10 题的证据规范化发生变化，其中 9 题消除了采集适配错误；真实超时仍保留。

## 公开语料：排序收益应与召回和可用性分开看

SciFact 全部 5,183 篇摘要切成 17,031 个三句片段。原 dev 的 300 条声明作为测试，另有 537 条与测试问题及目标文档不重合的开发题。目标文档来自 `cited_doc_ids`；188 题有原始人工句子 rationale，112 题没有这类证据标签，不能视为无答案。

| 方案 | 成功任务 | 文档 Recall@5，300题 | 证据组 Recall@5，188题 |
|---|---:|---:|---:|
| BM25 | 300/300 | 63.44% | 77.13% |
| Dense | 300/300 | 76.83% | 89.89% |
| Hybrid，固定 RRF | 300/300 | 75.89% | 87.77% |
| Hybrid + 重排，首轮原始记录 | 225/300 | 59.11% | 64.89% |
| Hybrid + 重排，可用性控制轮 | 300/300 | 80.40% | 90.43% |

公开实验的 Dense 使用当前 Qwen3-Embedding-8B 路由，重排使用 Qwen3-Reranker-8B；融合的词面分支为 BM25。该组件实验不是生产 BGE-M3 管线，也不是官方 BEIR 排行榜成绩。每题的一个完整 rationale 为一组，因此本表证据组 Recall 与本轮证据齐全率数值相同。

**Dense 相对 BM25 有明确的本样本收益。** 文档 Recall@5 增加 13.38 个百分点，配对 95% 区间为 **[7.13, 19.12]**；证据组 Recall 增加 12.77 个百分点，区间为 **[6.49, 19.23]**。

**固定权重融合尚未显示额外收益。** Hybrid 相对 Dense 的证据组 Recall 差值为 -2.13 个百分点，区间 **[-6.74, 2.30]** 跨过零。这一结果支持继续检验融合权重与候选质量，不能据此断言混合检索普遍更差。

**重排对文档排名的收益大于目前能确认的证据收益。** 控制轮相对 Dense 的文档 Recall@5 增加 3.57 个百分点，区间 **[0.14, 7.21]**；证据组 Recall 只增加 0.53 个百分点，区间 **[-3.26, 4.12]**。后者尚不足以确认稳定提升。区间未经多重比较校正，属于探索性证据。

在 188 道有 rationale 的题中，Dense 前 50 条已经找齐 **187 题**，前 5 条找齐 **169 题**；控制轮重排前 5 条找齐 **170 题**。本集合上，优先改进证据在前列的排序比继续放大候选上限更值得验证。

首轮重排发生一次连接错误，随后 74 题因模型健康冷却被立即拒绝。全部 75 次失败保留在分母。另开完整 300 题的控制轮，让后续题在调用前等待冷却结束，本题失败不重试。两轮差异也包含服务状态变化，不能全部归因于等待策略；首轮的零耗时拒绝不能作为重排速度优势。

预计算后，Dense 本地查询 P50 为 8.90ms，控制轮重排 P50/P95 为 0.74s/1.22s。它们不包括共享 embedding 准备：17,031 个语料片段和全部 837 个开发/测试查询共记录 **2,003,136 token**。重排 API 未报告完整 token 用量，不能据此给出总金额或声称零成本。

## 本地系统：收益随任务类型变化

本地包含 24 道文本、16 道图片、12 道音频、20 道视频、4 道跨模态和 4 道无答案题。文本仅涉及 3 份文档；80 题按共享来源合并后只有 **35 个独立样本组**。这些是依据现有索引内容编写并核对的题，不是独立人工盲标，也没有全面认证原始媒体内容。

| 模式 | 任务记录 success | 全部必需证据找齐@5，76题 | 找齐@50，76题 | P50 / P95 |
|---|---:|---:|---:|---:|
| Direct | 80/80 | 80.26% | 80.26% | 12.44s / 17.92s |
| 旧 Agent | 80/80 | 89.47% | 97.37% | 24.39s / 50.39s |
| Pi | 79/80 | 85.53% | 93.42% | 31.18s / 68.79s |

Pi 原生状态为 76 completed、3 partial、1 cancelled；partial 保留为已完成的检索观察，另标终态，取消题按失败计零。Pi 按首次取得证据的顺序计分，包含规划、工具和回答过程；Direct/旧 Agent 的时间只覆盖检索。各模式并发 2、共享本机和远端服务，时间只描述本轮负载。

此外，原生输出上限不同：本轮 Direct 最多交付 10 条，旧 Agent 30 条，Pi 35 条。因此 @50 是各模式最终交付集合的覆盖率，不能解释为相同证据预算下的算法比较。

前 5 条的比较仍不确定：旧 Agent 相对 Direct 的证据齐全率增加 9.21 个百分点，区间 **[-3.19, 26.76]**；Pi 相对 Direct 增加 5.26 个百分点，区间 **[-5.13, 20.37]**。扩大独立来源有助于缩小这里的不确定性。旧 Agent 的最终交付集合比 Direct 多覆盖了 13 道题，但其执行与证据预算也更大。

|---|---:|---:|---:|---:|
| 含文档证据 | 25 | 84.00% | 68.00% | 72.00% |
| 含图片证据 | 19 | 63.16% | 94.74% | 89.47% |
| 含音频证据 | 14 | 71.43% | 100.00% | 85.71% |
| 含视频证据 | 22 | 90.91% | 100.00% | 86.36% |

模态切片包含跨模态题，彼此重叠；跨模态只有 4 题，不能外推其百分比。切片提示旧 Agent 的聚合提升主要来自媒体任务，文档题前列证据存在回退，值得检查查询扩展和最终证据排列。Pi 另产生 **47 条**媒体观察/计算，没有与之对应的冻结文本真值，因此不纳入当前索引证据分；其完整收益需要原始媒体和答案质量评测。

Direct 的 76 道有证据题中，61 题已在前 5 条找齐，11 题的最终交付结果未包含目标来源，4 题看到了目标来源但证据不完整。旧 Agent 则有 6 题的完整证据在前 5 条之外，另有 2 题最终仍不完整。这些分类指向不同问题；最终结果缺失不能直接归因于最初候选召回，下一步还应记录并评分重排前的候选。

三种模式在 4 道无答案题上都返回了候选。这里测的是检索结果，不代表它们生成了错误答案；最终正确拒答率本轮没有评分。

| 已报告用量 | Direct | 旧 Agent | Pi |
|---|---:|---:|---:|
| 已知 token | 415,032 | 806,121 | 6,200,004 |
| 用量未知的调用计数 | 86 | 322 | 1 |

Pi 还有 1 个取消任务的未完整结算用量。三种模式工作范围不同、计量也不完整，不能将已知 token 的比例当成完整成本比例。Direct/旧 Agent 分别记录到 17/69 个取消的模型尝试；旧 Agent另有 14 个 transport 类失败尝试。取消可能来自调用方预算，不能都归为服务商故障；任务成功也不代表所有内部模型尝试成功。

## 下一步优化顺序

1. **先扩独立来源与可信真值。** 建议下一阶段收集约 300 道中文业务题，优先新增文档/媒体来源和真实用户表达，具体数量再由需要检出的差值及实测方差决定。保留改写、精确实体、数值、多证据、范围、困难负例与无答案切片；抽取不同检索器的候选联合盲标，减少未判定结果造成的偏差。原始媒体需核对图片区域、视频时间段和转写。开发、回归与未接触过的保留集分开。
2. **依据错误类型优化检索。** 在公开集合上优先验证前列证据排序；在本地补齐重排前候选的记录，以区分召回缺失、重排丢失和上下文裁剪。重点复查文档题的 Agent 排序回退与 Direct 的媒体遗漏。
3. **补同预算与端到端对照。** 控制工具次数、证据条数、模型及总时间后再比较模式；另测最终回答正确性、引用支持度和正确拒答。当前分数不足以把所有请求统一切到某种 Agent 模式。
4. **把可靠性和成本纳入门禁。** 分开统计真实请求失败、预算取消、冷却拒绝与解析错误；补齐 rerank 等用量。保持完整分母、版本化数据和显式配置差异，结合切片与区间作决定，避免只看一个平均分。

扩充数据集是下一阶段的重要投入，最有价值的增量是**独立来源、真实问题和可核验的证据**。这比在现有少数文档上继续堆积相似问题，更能帮助决定检索优化方向。
